## 发布页"订阅评论消息提醒"开关状态不一致排查

用户反馈:图一(微信原生订阅授权弹窗)勾选两个模板并点允许;图二(发布页顶部入口卡片)开关仍显示为关闭(灰色)。

排查结论: **不是授权失败,是设计内行为**。

关键代码路径:
- `pages/post-publish/index.js` 第 58-70 行 `refreshCommentSubscribeEntry`:每次入口显隐重算都硬重置 `commentSubscribeChecked = false`,无论本地是否已授权。
- `utils/subscribe.js` 第 406-409 行 `entryVisibleAsync`:本地"已订阅"时仍会查 `/api/v1/subscribe/quota`,**额度耗尽会强制让入口重新出现** —— 这是项目为解决"订阅了却一直收不到"问题的有意设计。
- `utils/subscribe.js` 第 339-378 行 `requestEntryByTap`:授权成功后写本地 `subscribe_comment_prefs` 并 `reportQuota` 上报额度 +1。

最常见根因 (按概率):
1. 服务端评论/私信额度被高频场景用尽(最常见)
2. `fetchQuota()` 异常被 `pages/post-publish/index.js` 第 65 行 `.catch(() => {})` 静默吞掉
3. `persistAccepted` 写本地失败
4. 微信侧"总是拒绝"导致 accept 静默返回 reject

排查方法:
- 真机 vConsole Network: 触发授权 → 看 `POST /subscribe/report` 返回 quota; 返回发布页 → 看 `GET /subscribe/quota` 的 `commentNew` / `commentReply` 值
- `wx.getStorageSync('subscribe_comment_prefs')` 看本地是否含 `commentNew=true, commentReply=true, grantedCommentNew=true, grantedCommentReply=true`

可执行优化建议:
- 入口重现时给出"额度已用尽,再点一次重新授权"toast(避免用户误以为授权失败)
- `commentSubscribeChecked` 根据本地 granted 计算,而不是硬重置为 false
- `fetchQuota()` 失败不要静默吞错,加 `console.warn`
- 服务端 `quota` 接口同步返回 `exhaustedTypes`,前端针对性提示
- `persistAccepted` 加 try/catch,失败落 warn

## 订阅消息额度模型(权威事实)

**不存在"每个订阅固定多少额度"**。额度是动态累加的:

- `server/services/subscribeService.js` 第 140-154 行 `grantQuota`:用户每点一次「允许」→ `INSERT ... ON DUPLICATE KEY UPDATE remain = remain + 1, total_granted = total_granted + 1`。**点 N 次 = N 条**。
- 第 206-211 行 `consumeQuota`:发送成功才扣,`remain = GREATEST(0, remain - 1)`。**发送失败不扣额度**。
- 第 213-218 行 `clearQuota`:微信返回 43101(用户拒收)→ 该模板额度**清零**。
- 表 `user_subscribe_quota`(migrations.js 第 1088-1097 行):主键 `(user_id, tpl_type)`,`remain DEFAULT 0`。**20 个模板类型互相独立,不共享额度池**。
- 这是微信「一次性订阅消息」的官方约束(点一次允许 = 一条可发),非项目自定义。

**额度消耗的减速机制**:
- `MERGE_WINDOW_MS`(第 48-53 行):仅 3 个高频模板有 5 分钟合并窗口 —— `commentNew` / `commentReply` / `message`。窗口内同类消息只发一条,后续落待发表**且不扣额度**;其余(交易/资金/审核/活动)低频重要,**不合并**。
- `subscribe_pending_message` 待发表:额度不足或命中窗口时内容不丢弃,等额度恢复补发;单槽位最多 `MAX_PENDING_RETRY = 15` 次(约 30 分钟),`DEFER_RETRY_DELAY_SEC = 120`。
- 每个 `(user_id, tpl_type)` 槽位**只保留最近一条**,窗口内来 10 条评论最终只补发 1 条(内容取最新)。
- 额度耗尽时发站内信「微信提醒次数已用尽」,按 `(user, tpl_type)` 24 小时节流(`QUOTA_NOTICE_THROTTLE_MS`)。

**20 个模板类型**(`TPL_TYPES`):commentNew / commentReply / withdrawSuccess / withdrawResult / activityNew / activityJoined / activitySignupNotice / activityAudit / activitySignupResult / activityStart / activitySignup / errandAccepted / errandFinished / errandCancelled / auditCert / audit / auditPass / message / userPmNotice / reportResult。其中 `userPmNotice`、`reportResult` 已注册但暂无业务触点(备用)。

**查询额度**:`GET /api/v1/subscribe/quota` → 返回全部 20 个模板的 `remain`(未授权的模板补 0)。
