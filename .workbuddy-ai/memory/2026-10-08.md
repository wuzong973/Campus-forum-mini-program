## 修复回归 3：「底部永远露一条 tabbar」

**现象**（用户重传后实测截图）：黑底全屏、无标题栏、图片居中都对了，但底部仍是一条白色 tabbar。

- 调用点：`toggleQrZoom`（放大 true / 缩小 false）；**恢复点齐全**：`stopPropagation`（点任意处收起）、`closeQr`、`contact-admin` 的 `pageLifetimes.hide` + `lifetimes.detached`、`push-groups` 的 `onHide`。**漏一个 = 那个 tab 页的 tabBar 永久消失。**

**护栏**：④b 组新增 ⑥⑦ 断言（放大必须调 `setTabBarHidden` / 必须走 `getTabBar` 且判空 / 收起与关闭必须恢复 / custom-tab-bar 的 `hidden` 默认值与 `wx:if`）。

## 首页轮播填了跳转路径却跳不动 —— 根因是「分包路径」+「硬编码白名单」

**用户现象**：后台「编辑首页轮播」的「点击跳转路径」填了 `/pages/review/target?id=9`，
点击轮播**完全没反应**（无报错、无提示）。

**三层问题叠加**：

1. **路径缺分包前缀**。本项目 35 个页面在 **`pkg-feature` 分包**里，真实路径是
   `/pkg-feature/pages/xxx`，**不是** `/pages/xxx`。用户想跳的「校园活动」真实路径是

   什么都不做。
3. **`indexOf('index') > -1` 子串匹配会误伤**：正确路径

## 首页轮播点了弹「链接已复制」—— 库里存的是微信小程序短链

**用户现象**：首页轮播（校园恋综）点了弹「链接已复制」，不跳转。

**根因（只读探针查出来的，别靠猜）**：`system_content` 里那行 banner 的 `meta.link`
实际是 **`#小程序://帕云校园/t1CRvODJjcaMhGr`**（字符码 `35,23567,31243,24207,58,...`
= `#` + 小程序://…），**不是页面路径**。端上 `utils/link` 判它既不是站内路径也不是外链
→ 走复制兜底。**代码行为是对的，是这个值本身跳不了。**

⚠ 关键区分：`#小程序://xxx/yyy` 是**微信「小程序短链」**，**只能粘进微信聊天里点开**
（`services/groupBroadcastService.js` 的群发就靠它，`group-broadcast.test.js` 明确
「短链保持原文，不被改写，改写后聊天里点不开」）。**小程序内部没有任何 API 能用它跳转。**
所以它**不能**作为轮播/自定义页的跳转目标。

**为什么能被存进去**：首页轮播的 `link` 在 `body` JSON 的 `meta.link` 里，
而 `adminController.createContent/updateContent` **从不校验 body 内容**，
`pkg-admin/admin/edit` 的 `buildPayload` 也只校验了标题+图片。**两处都没有链接校验**
（旧后台 `pkg-admin/admin/index.js` 也没有 → 不是分包迁移丢的，是从来没写过）。

**修复（三层）**：
1. **新建 `server/utils/link.js`** —— 服务端链接校验唯一来源，与端上 `utils/link.js` 对称：
   `isNavigableLink(url)` / `linkRejectReason(url)` / `WX_CHAT_SHORT_LINK_RE`。
   `configController.js` 删掉本地 `PAGE_LINK_RE`，改引用它（两处调用点）。
2. **保存时就拦**：`adminController` 加 `bannerLinkRejectReason(type, bodyText)`
   （只对 `type==='banner'`），`createContent`/`updateContent` 在 **INSERT/UPDATE 之前**校验；
   `pkg-admin/admin/edit` 的 `buildPayload` 同步校验（用 `wx.showModal`，原因长 toast 会截断）。
3. **运行期提示说清原因**：`pages/index/index.js` 兜底文案从「链接已复制」
   改成「该链接无法跳转，已复制」（`icon:'none'`）。
   `#小程序://` 有**专门**提示（点明是短链 + 给出 `/pkg-feature/pages/activity/index` 示例）。

**护栏** `server/tests/miniprogram-link-routing.test.js`（17 → **20** 条）：
新增 D 段「端上/服务端同一张用例表比对」（15 个用例 × 两个模块，防止两个运行时各自漂移）、

### 追加：页面路径带 `.html` 后缀 —— 前缀对了照样跳不了

### ⚠ 冒烟测试立刻抓到一个我引入的真 bug

`normalizePagePath` 的「去掉站点域名」规则**太宽**：
`https://payun01.cn/page.html`（运营有意配的**本站外链**，本意走 webview 打开网页）

表现成**「明明是合法外链却保存不了」**。

修法：**只有「去掉域名后确实是小程序页面路径（`INNER_PATH_RE` 命中）」才改写**。
`https://payun01.cn/pkg-feature/pages/x` → 改写 ✓；
`https://payun01.cn/page.html` / `/wechat-qr.html` / `/uploads/a.jpg` → 原样不动 ✓。

只有真的把值喂进函数跑一遍才会暴露。

**教训**：**静态扫描只能证明「代码长得对」，证明不了「跑得起来」。**
页面/组件的关键方法（加载、保存、事件回写）应当用 vm 沙箱做**行为**冒烟，
尤其是重构「删代码」时 —— 语法检查与字符串断言对「漏删引用」完全无感。
