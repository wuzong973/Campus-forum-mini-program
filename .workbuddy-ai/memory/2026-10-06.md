## 后续 2：解冻后仍显示「待解冻」（用户第三次反馈）

### ⚠ 写这类静态断言踩的三个坑（本组守卫连挂三次）
1. **别用 `\s*$` 断言「字段在返回对象里」** —— 对象字面量最后一个键后面没有逗号，`/unfrozen,\s*$/m` 不匹配。
   正确：把 `return Object.assign({}, r, {` 到紧随 `})` 之间切出来，再 `^\s*unfrozen,?\s*$` 匹配。
2. **别用固定长度 `slice(start, start+40)` 取标签** —— `<view class="runner-actions" wx:if="{{item.frozen}}">`

3. **三元拼出来的类名 grep 不到** —— `st-{{... 'frozen-lifted' ...}}`，WXML 里**不存在** `st-frozen-lifted` 字面量。
   断言要匹配拼装片段 `/st-\{\{item\.frozen[^}]*'frozen-lifted'/`，不能直接 `test('st-frozen-lifted')`。

## Phase I：消息点评论 → 直接进详情并定位高亮（2026-10-06 晚）

### ⚠️ 关键坑：`scroll-into-view` 与高亮必须解耦
`scroll-into-view` **值被清空会立刻跳回顶部**，且**只在值变化时才触发滚动**。

## ⚠️ 「首页校园市场图标还是不显示」根因：微信不认内联 SVG 里的 `<g>` / `transform`

### 现象
上一轮把图标改成 `<g transform='scale(0.0234375)'><path .../></g>` 后，用户截图反馈**仍然空白**。

### 排查（不要止步于「代码看起来对」）
逐层排除，全部正常：`service_item` 表（**生产库根本没有「校园市场」这条**，所以走 else 分支）→
`buildHomeGrid` 的 `uiIcon = def.iconPath ? '' : (def.uiIcon || '')` → WXML 三态分支 →
`app.wxss` 的 `@import` → `.icon-wrap .ui-icon` 尺寸 → `project.config.json` 的 packOptions（未忽略 `styles/`）。

### 决定性证据：与项目「能正常工作的先例」对比结构
项目里 5 处**可正常工作**的内联 SVG（`post-card` 星标、`post-detail` 点赞、`index` 评论面板心形）
**全部是 `<svg>` 直接包 `<path>` 的扁平结构**；
而 `grep` 全项目 `<g>` / `transform=` —— **只有我新加的 market 图标这一处**。

**结论：微信小程序 WXSS 的 `background-image` 对内联 SVG 的解析不如浏览器宽容，
`<g>` / `transform` 会导致整张图「静默渲染失败」**（格子空白、控制台无任何报错），
极易被误判成「图标没配 / 数据没下发」。

### 修法：把坐标真正算好，不套 transform
用脚本按 SVG path 语法（含 `A` 弧线的 `rx/ry/rot/large/sweep/x/y` 分别处理，**只缩放 rx/ry/x/y，
不动 rot/large/sweep**）把 1024 网格的路径整体缩放到 24 网格（系数 24/1024），
产出与先例**完全同构的扁平 `<svg><path/></svg>`**。视觉经浏览器渲染逐像素比对等价。

### ⚠️ 更严重的连带发现：护栏 B4 自建立起就是「空判据」
`ui-icons-shared.test.js` 里提取 data-uri 的正则写作：
```js
ICONS_WXSS.match(/data:image\/svg\+xml,[^"']*/g)
```
`[^"']*` 排除了单引号，而 **SVG 内部必然含单引号**（`viewBox='0 0 24 24'`）——
匹配**在第一个单引号处就截断**，实际只取到 32 字符的 `data:image/svg+xml,%3Csvg xmlns=`。
后果：**B4（`#` 必须转义为 `%23`）从建立起就从未真正检查过任何内容，恒通过 = 假绿灯**。

**修法**：改用起始锚定 + 配对引号的正则，一路取到 `url(...)` 右括号：
```js
/url\(\s*(["'])(data:image\/svg\+xml,[\s\S]*?)\1\s*\)/g
```
修正后 7 个 uri 的提取长度从 **32 → 376~680**。

### 新增护栏 B4b + 反向验证
新增断言：**内联 SVG 必须是扁平结构（禁用 `<g>` / `transform`）**，并**做了反向验证**：
| 样本 | 修正提取长度 | 旧错误提取 | 判据结果 |
|---|---|---|---|
| 含 `<g transform>` | 177 | 32 | **FAIL ✅ 被拦下** |
| 扁平结构 | 153 | 32 | PASS ✅ |
| 未转义 `#` | 129 | 32 | **FAIL ✅ 被拦下** |

`ui-icons-shared.test.js` 现 **29 项断言全通过**（28 → 29）。

### 通用教训（已写入 MEMORY.md）
1. **「静态断言恒通过」比「没有断言」更危险** —— 每次新增/修改静态守卫，必须用「改坏源 → 必须 FAIL」
   反向验证；本次正是反向验证暴露出 B4 是空判据。
2. **提取 CSS 里的 `url(...)` 不要用 `[^"']*`** —— 内容自身含引号时会静默截断。
   必须以配对引号/右括号锚定。
3. **给外源 SVG 归一化坐标系时，不要用 `<g transform>`** —— 小程序可能静默不渲染。
   要把坐标算好产出扁平结构（与项目既有成功先例保持同构）。
4. **排查「元素不显示」时，第一件事是对比「同一个项目里能正常工作的同类先例」**，
   结构差异往往就是答案（本次 `<g>` 会立刻暴露）。

1. **无「楼主」概念** → 删除权限矩阵里「对方可删」一档**不适用**，建议**仅「评论作者 + 管理员」**。
2. **无「蹲对象」概念** → `follow` 通知天然不适用。
3. **无 `comment` 通知**（评价对象非 UGC，无作者）→ 只需 `reply` / `like`。
4. **排序默认**：帖子 `hot`、评价 `time`（点评场景最新更有价值）——合理。

- 修法：**按标签名做配对扫描**（`depth` 初值 **1** —— 容器自身开标签已计入；只对同名标签配平，内部 `image`/`button`/`text` 不能一起数），得到容器真正的收口位置再比较。
- **`depth` 初值 0 也是错的**：那样扫到的第一个内层元素收口就会让 depth 回 0，同样得出错误位置。
- **做改坏补丁时注意换行符**：仓库 wxml 是 **LF**，写 `\r\n` 的 `assert anchor in s` 会直接抛错（好在有 assert，没静默跳过）；另外**「只删注释」不等于「改坏了结构」** —— 第一版补丁删了注释就以为把操作栏挪进去了，其实 `<view>` 还留在原地。
