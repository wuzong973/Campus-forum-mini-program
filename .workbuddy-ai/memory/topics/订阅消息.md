# 订阅消息（server/services/subscribeService.js）

> 从 `MEMORY.md` 拆出（2026-10-06）。细节另见 `docs/订阅消息_*.md`。

- **⚠ `access_token` 必须走 `cgi-bin/stable_token`，绝不能回 `cgi-bin/token`**：后者**每调一次作废上次 token**，而 cluster 2 实例、`cachedToken` 是**进程内变量** → A 刷新后 B 立刻失效 → `40001 ... not latest`。`forceRefresh: true` **只允许在 40001/42001 自愈路径用**。**`scripts/verify-wechat-config.js` 是地雷**（跑一次废掉线上 token），已改。
- **`skipped`/`throttled`/`failed` 完全不同**：`remain <= 0` → `skipped` 并 return，**压根没调微信**；被微信拒（带 errcode）才 `failed`（**与额度无关**）；`throttled` 是**客户端弹窗节流**命中。`failed` 还含「异常不写日志」。
- **「授权弹窗触发点」唯一姿势**：业务 tap 里调 `requestTriggerByTap('<组>')`，**必须在 tap 同步链内**（放 `onLoad`/`setTimeout`/`then` 会静默失败），且在前置校验之后、任何 `await` 之前。8 组固定：`postPublish`/`errandPublish`/`withdraw`/`message`/`riderVerify`/`activityPublish`/`activitySignup`/`activityIndex`，**不要新建组或模板**。节流层 `utils/subscribe.js`：同组**未勾「总是允许」**一天最多 3 次（本地键 `subscribe_popup_throttle`，`day` 用**本地**时区、跨天惰性重置）；**必须本地存储**；勾「总是允许」→ 跳过节流但仍照常调用。
- **额度按 `(user_id, tpl_type)` 逐人独立存**（点一次「允许」= 1 条，`43101` 清零）。看板「剩余」是总、「N 人有额度」(`availableUsers`) 才是真能收的人数。`/subscribe/quota` 返回 `{data:{quota:{模板:条数}}}`，客户端要取 `.quota`（曾漏解 → 入口永不消失）。
- **空值字段铁律**：`data` 里任何空值字段微信返回 `47003`（不可重试）。必须 `clipOr(x,n,兜底)`；`date`/`time` 也拒空。字段名要 `GET /wxaapi/newtmpl/gettemplate` 拉真实结构比对，**不要靠猜**。
