## 顺手修掉 miniprogram-static-audit 技能的两个脚本缺陷

用技能体检时发现它自身有问题，按「技能有问题就地修正」的约定改了 `scripts/audit.py`：

1. **`async` 方法被漏判成「未定义」**：`check_this_calls` 的「定义」正则只认 `^  name(` / `^  name:`，
   `async onSubmit() {` 匹配不上 → 本项目一次性误报 7 处（全在未改动文件里）。
   修法：抽出 `ASYNC_PREFIX = r'(?:async\s+)?'` 加到三处正则（定义 / 键值定义 / 重复定义）。
   修后本项目 0 误报。
2. **根目录不对时静默「体检通过」（假绿）**：各 `check_*` 找不到子目录就 `return`，
   `main()` 最后照打「未发现问题」。踩到的具体场景：在 Windows 上把 Git Bash 风格的
   `/tmp/xxx` 绝对路径传进去，原生 Python 解析成 `C:\tmp\xxx`，什么都检查不到却说通过。
   修法：`main()` 加前置校验（目录存在 + 有 `app.json` + 有 `pages/`），不满足打印
   `[根目录不存在] / [不是小程序根目录]` 并 **退出码 2**。

**双向验证**（这一步不能省，否则「治绿」比误报更危险）：
- 真实仓库：`未发现问题，静态体检通过。` 退出码 0。
- 构造坏样例（`this.reallyMissingMethod()` + wxml 绑 `handlerNotWritten`，另含 `async onLoad/loadThing`）：
  仍准确报出那 2 处真问题（退出码 1），且 async 方法不再误报。
- 不存在的绝对路径：显式 `[根目录不存在]` + 退出码 2，不再假绿。

SKILL.md 同步补了「退出码判据表」「async 正则必须反向验证」「不许用加白名单消除报错」三条注意事项。
