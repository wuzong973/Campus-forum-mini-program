# 核心业务流程说明

## 1. 总体说明

当前项目的核心业务流程可以分成四条主链：

1. 小程序用户登录与身份建立
2. 课程表读取与首页提醒
3. 教务系统课表同步
4. 社区内容与私信互动

其中，本次改造重点是第 3 条，即“同步我的课表”的完整闭环。

## 2. 用户身份链路

## 2.1 微信登录

前端入口：

- `pages/login/index`
- `utils/auth.js`

后端入口：

- `POST /api/v1/user/phone-login`
- `server/controllers/userController.phoneLogin`

执行过程：

1. 小程序获取微信登录 `code`
2. 小程序获取手机号授权 `phoneCode`
3. 后端调用微信接口换取 `openid` 与手机号
4. 后端按手机号优先匹配 `sys_user`
5. 后端签发 JWT
6. 前端保存 `token` 与 `userInfo`

身份结果：

- 小程序内的业务鉴权依赖 JWT
- `req.userId` 成为后端所有业务数据隔离依据

## 2.2 用户身份与课表同步的衔接

课表同步接口必须先经过 JWT 认证：

- 未登录：前端直接拦截，不允许进入同步链路
- 已登录未认证学号：允许输入教务账号同步
- 已认证学号：仅允许同步与当前认证学号一致的教务账号

这样做的目的是避免用户登录他人教务账号并把他人课表写入自己的业务账户。

## 3. 课程表读取链路

## 3.1 课表列表加载

前端入口：

- `pages/schedule/index`
- `pages/index/index`
- `utils/api.getScheduleList`

后端入口：

- `GET /api/v1/schedule/list`

执行过程：

1. 前端请求后端课表列表
2. 后端读取 `user_schedule`
3. 前端标准化课程字段
4. 按当前周次过滤 `startWeek / endWeek / weekType`
5. 课表页渲染周视图
6. 首页按“当前周 + 今天星期 + 单双周”提取今日课程提醒

## 3.2 课表页当前周过滤规则

课表页当前的展示规则为：

1. 当前周必须在 `startWeek <= currentWeek <= endWeek`
2. `weekType = all` 直接展示
3. `weekType = odd` 仅奇数周展示
4. `weekType = even` 仅偶数周展示

这保证了整学期课表入库后，前端仍然只展示当前周有效课程。

## 4. 教务系统课表同步主流程

## 4.1 用户触发

入口页面：

- `pages/schedule/index`

触发方式：

1. 用户打开课程表页左侧抽屉
2. 点击“同步我的课表”
3. 前端先检查是否已登录小程序
4. 已登录则跳转 `pages/schedule-login/index`

## 4.2 教务登录页交互

页面：

- `pages/schedule-login/index`

交互元素：

1. 教务账号输入框
2. 教务密码输入框
3. 登录提交按钮

页面逻辑：

1. 若当前用户资料中已有 `studentId`，自动回填到账号输入框
2. 用户输入密码并点击“同步课表”
3. 前端调用 `api.syncSchedule(username, password)`
4. 请求层使用更长超时，避免批量抓取被前端 15 秒超时提前截断

## 4.3 后端同步接口

接口：

- `POST /api/v1/schedule/sync`

后端步骤：

1. 校验 JWT
2. 校验账号密码非空、账号格式合法
3. 若用户已认证学号，则校验输入账号必须一致
4. 读取用户 `schedule_config.start_date`
5. 调用 `jwScheduleSyncService.syncScheduleFromJw()`

## 4.4 爬虫适配服务流程

服务文件：

- `server/services/jwScheduleSyncService.js`

执行过程：

1. 创建 `JwCrawler` 实例
2. 注入 OCR 语言包路径与超时、限流参数
3. 按配置的登录模式登录教务系统
4. OCR 自动识别验证码
5. 逐周抓取课表 HTML
6. 解析为课程数组
7. 将多周课程聚合成标准结构

聚合结果字段：

- `name`
- `location`
- `teacher`
- `weekDay`
- `startTime`
- `endTime`
- `startWeek`
- `endWeek`
- `weekType`
- `color`

## 4.5 数据入库流程

控制器在同步成功后执行：

1. 开启数据库事务
2. 删除该用户旧课表
3. 插入新课表记录
4. 提交事务
5. 返回课程数组与学期开始日期

入库表：

- `user_schedule`

本次新增字段：

- `week_type`

用途：

- 用于表达单双周课程，支撑当前周正确过滤

## 4.6 前端同步成功后的收口

同步成功后：

1. 将课程数组写入本地 `schedule_courses`
2. 将后端返回的 `startDate` 写入 `scheduleConfig`
3. 返回上一页
4. 课表页 `onShow` 重新计算当前周并重新拉取列表

最终结果：

- 本地缓存已更新
- 后端数据库已更新
- 页面展示已刷新

## 5. 教务系统同步异常处理

## 5.1 前端输入校验

场景：

- 学号为空
- 密码为空

处理：

- `wx.showToast`

## 5.2 后端权限校验失败

场景：

- 未登录
- 当前用户与认证学号不匹配

处理：

- 后端返回 `401/403`
- 前端弹框提示

## 5.3 登录失败

场景：

- 教务账号错误
- 教务密码错误
- 教务系统返回“请先登录系统”

处理：

- 服务层统一归一化为“教务系统登录失败，请检查账号或密码”

## 5.4 网络异常

场景：

- 连接重置
- DNS 失败
- Socket 异常

处理：

- 服务层统一归一化为“网络异常，暂时无法连接教务系统”

## 5.5 爬虫请求超时

场景：

- 登录接口超时
- 周课表抓取超时

处理：

- 服务层统一归一化为“爬虫请求超时，请稍后重试”

## 5.6 验证码识别失败

场景：

- OCR 连续失败
- 教务系统返回验证码错误

处理：

- 服务层统一归一化为“验证码识别失败，请稍后重试”

## 5.7 数据解析失败

场景：

- 无法提取 `sjmsValue`
- 课表 HTML 结构异常

处理：

- 服务层统一归一化为“课表数据解析失败，请稍后重试”

## 5.8 频率保护

场景：

- 用户连续频繁点击同步
- 同一用户重复触发同步任务

处理：

- 同一用户同步中再次触发，直接拒绝
- 同一用户短时间内重复同步，返回限频提示

## 6. 首页课表提醒流程

入口页面：

- `pages/index/index`

执行过程：

1. 读取课程表列表
2. 根据 `scheduleConfig.startDate` 推导当前周
3. 根据今天是周几过滤当日课程
4. 根据 `weekType` 判断单双周是否命中
5. 根据结束时间判断“今日剩余几节课”
6. 将结果渲染到首页提醒卡片/横幅

## 7. OCR 导入流程

入口页面：

- `pages/schedule-ocr/index`

后端接口：

- `POST /api/v1/schedule/ocr`

当前逻辑：

1. 前端上传 OCR 文本或截图
2. 后端按规则解析课程文本
3. 对低置信度课程给出提示
4. 识别结果可再导入为正式课表

这条链路与教务同步链互补：

- OCR 适合截图导入
- 教务同步适合直接从系统拉全量课表

## 8. 社区与私信主流程

## 8.1 社区内容链

1. 首页加载帖子流
2. 进入帖子详情
3. 可执行评论、点赞、收藏、转发
4. 数据分别落到 `forum_post / forum_comment / forum_like / forum_favorite / forum_share`

## 8.2 私信链

1. 登录成功后 `app.onLogin()` 建立 WebSocket
2. `messageStore` 同步未读数
3. 聊天页走消息接口 + WebSocket 实时收发

## 9. 当前流程结论

当前项目的关键业务闭环已经形成以下统一模式：

```text
页面操作
  -> 前端 API 封装
  -> 后端鉴权与业务控制器
  -> 服务层聚合
  -> 数据库存储 / 外部系统调用
  -> 返回前端刷新本地状态
```

本次课表同步改造完成后，项目在“微信身份 -> 小程序用户 -> 教务同步 -> 课表展示 -> 首页提醒”这一链路上已经具备完整闭环能力。
