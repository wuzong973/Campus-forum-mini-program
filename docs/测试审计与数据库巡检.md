## 六、遗留问题与后续建议（汇总未闭环项）

### 6.1 提审阻断（P0，以 2026-08-25 报告为准）

1. 真实后端链路不可证明可用：MySQL/Redis 须于类生产环境执行接口回归，保存请求/响应、数据库写入与回调证据。
2. 密钥轮换未完成：已暴露的微信/数据库/JWT/支付密钥须全部吊销轮换，并清理 Git 历史（`.env` 已占位、私钥已删）。
3. 支付与钱包高风险：维修支付、跑腿支付、退款、钱包提现须完成商户号/证书/平台公钥、回调 HTTPS、金额校验、退款/提现审核、对账、异常补偿、管理员通知验收；完成前正式包隐藏/关闭钱包与支付入口。

### 6.2 高危功能缺陷（HIGH，以 2026-09-12 报告为准，全部待修）

- H1 教务密码错 401 → 全局登出（改 400）
- H2/H3 课表编辑=重复新增、删除=清空重插丢数据（补单条接口或改 `/schedule/replace`）
- H4 活动详情 `AUDIT_TIP` 未定义 → 创建者打不开自己活动（定义常量）
- H5 注销功能从未真正删除账号（加定时任务扫描 `account_deletion_request`）

### 6.3 数据库根因（以 2026-09-10 报告为准）

- 微信支付商户号「基本账户」余额不足导致退款永败；须充值 + 加重试上限（否则清完再生，约 144 条/天）。
- `init.sql` 已补齐 52 表完整版并部署；`post_view`/`errand_review` 等死表死字段待清理或补展示。

### 6.4 综合建议

1. 优先闭环 H1–H5 与 P0 三项，再发起微信官方审核（提审版本不得含 Demo/Mock/占位支付）。
2. 完成隐私后台配置与真机同意/拒绝/撤回测试、外部 H5/AppId 白名单与 TLS 确认。
3. 上线前完成 iOS/Android 真机、弱网、长文本、401、WSS 重连、冷/热启动性能测试并保留 P50/P95。
4. MEDIUM/LOW 缺陷（接口分页、图片展示、周数口径、匿名会话、WebSocket 登出、各类死字段）排期渐进处理。
5. 群聊自愈逻辑改用 `deleted` 之外条件，避免重启复活已删群聊。
