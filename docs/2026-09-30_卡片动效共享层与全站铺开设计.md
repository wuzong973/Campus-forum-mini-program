# 卡片动效共享层与全站铺开设计

日期：2026-09-30
范围：把首页轮播已落地的「旋转描边 + 呼吸弥散背光」抽成共享层，铺到全站 10 个面（其中 9 面拿描边），
并补齐全站缺失的动效降级开关。**列表项只拿静态描边，自转保留给单实例主卡**（见 §2.7）。
**本轮不含 3D 倾斜跟随**——倾斜、触点光斑、流光带继续只留在首页轮播。

## 1. 背景

首页轮播（`pages/index/`）已单独实现这套效果并配了护栏测试 `server/tests/home-banner-press.test.js`。
直接逐页复制内联被否决，理由有两条实证：

- `app.wxss:290` 那段注释记录过「同一元素分页写，就是怎么调都对不齐的根因」；
- 首页的描边方块写死 820rpx，是因为轮播卡尺寸已知（710×266，对角线 758）。
  其余面的高度各不相同（`.hot-poster` 还是 `mode="widthFix"` 的自适应图），抄数值必然在某个面上露缺口。

## 2. 共享层 `styles/card-fx.wxss`

### 2.1 结构

```
.fx-stage                     承载背光。背光不能被裁，必须是卡片的兄弟节点
  .fx-glow-layer
    .fx-glow(.is-on)          交叉淡入：走 transition: opacity
      .fx-glow-pulse          呼吸脉动：走 animation，两者分开以免互相覆盖
  .fx-card                    卡片容器（position: relative，自身不裁切）
    .fx-ring                  圆角裁切层（overflow: hidden）
      .fx-ring-spin           自转方块，铺静态 conic-gradient
    .fx-body                  内容层，四边内缩 var(--fx-w)，露出的那一圈即描边
```

### 2.2 实例 token（内联 style 传）

| token | 含义 | 默认 |
|---|---|---|
| `--fx-accent` | 主色，描边与背光共用 | `#4A7AFF` |
| `--fx-w` | 描边宽度 | `4rpx` |
| `--fx-r` | 卡片外圆角 | `24rpx` |
| `--fx-bleed` | 背光下溢量 | `56rpx` |
| `--fx-side` | 描边方块边长；仅在卡片比例超出 §2.3 不变式时显式给 | 空（走 170% padding） |

`.fx-body` 的圆角由 `calc(var(--fx-r) - var(--fx-w))` 推出，不单独传，避免内外圆角不同心。

### 2.3 几何不变式（本轮最关键的一条）

`.fx-ring-spin` 用百分比 padding 强制正方形，绕开"每页要知道自己对角线"的问题：

```css
.fx-ring-spin {
  position: absolute;
  left: 50%; top: 50%;
  width: 170%; height: 0; padding-bottom: 170%;
  transform: translate(-50%, -50%) rotate(0deg);
}
```

百分比 padding 相对**包含块宽度**解析，所以边长恒为卡宽 ×1.7，与卡高无关。

**成立条件：卡高 ≤ 卡宽 × 1.63。** 超出该比例时方块盖不住对角线，旋转会在角上露缺口。
接入每一面前先核对该比例；不满足的面改用 `--fx-side` 显式给边长。

### 2.4 描边动画

- conic 角度无法直接补间（小程序 WebView 不支持 `@property`/Houdini），**转的是方块元素本身**。
- `background` 先写 `linear-gradient` 兜底、再写 `conic-gradient` 覆盖：不支持 conic 的内核退化为静态渐变边，而不是整圈无边框。
- 只在 `.is-live` 的实例上播放（`animation` 挂在 `.is-live .fx-ring-spin`），非可见实例连动画都不挂载，而不是 paused。
- 周期 4.5s。慢于 6s 时任一时刻近似纯色，读不出"在转"。

### 2.5 背光

- 用多档 `radial-gradient` 模拟弥散，**禁止 `filter: blur()`**。首页是长列表 + 九宫格图 + video 的主滚动面，常驻逐帧模糊掉帧明显，视觉却等价。护栏测试剥注释后扫描。
- 亮芯落在卡面下沿上，图层一半高度藏在卡片后面，只有下溢部分可见。
  下溢量 `--fx-bleed` 默认 56rpx。
- **接入前必须确认该面下方有 ≥24rpx 空隙**，否则背光会被下一个元素盖住。
  首页是靠把 `.banner-indicator` 下边距 18→44rpx 腾出空间解决的；不是每个面都值得为它改布局。
  空隙不足的面**只上描边、不上背光**。
- 背光层是 `z-index: 0` 的定位元素，而 `.fx-stage` 不构成 stacking context，会画在本应盖住它的普通流元素之上。
  下方紧邻元素需要 `position: relative; z-index: 1`（首页 `.notice-bar` 已这么处理）。**不要把背光压到 `z-index: -1`**，那会连页面底色一起垫到下面去。

### 2.6 内容高度守恒（首页踩过的坑）

描边是从 `.fx-body` 四周内缩"扣"出来的，等于内容区少了 `2 × --fx-w` 高。
轮播文字块按 258rpx 排版，扣完剩 250rpx 就会顶到裁切线，把顶部标签切掉半截，**且不报任何错**。
解法：容器高度由外层加回来，不从内容区出。共享层保留不变式断言：
`容器高 - 2×描边宽 >= 内容设计高度`。

### 2.7 列表项不旋转（本轮的性能红线）

`.club-card` / `.gc-card` / `.act-card` / `.card-entry` / `.school-card` 全都在 `wx:for` 里，是列表项。
每个列表项挂一个无限自转的 conic 合成层，滚动时是 N 层同时在转——这比首页单卡严重一个量级。

决定：**列表项只上静态渐变描边（`.fx-ring-spin` 不挂 animation），自转保留给单实例主卡**
（首页轮播、`.balance-card`、`.hero`、`.hot-poster`、`.promo`）。

这是对最初清单的一个收窄：原清单把这几面写成"适配倾斜+流光"，但倾斜本轮不做、旋转在列表里又不该开，
所以它们实际拿到的是「静态描边 + 视空隙而定的背光」。若观感上觉得"跟没加一样"，
备选方案是列表项改为**进场时转一圈后停住**（`animation-iteration-count: 1`），
比无限转便宜得多，又比纯静态有存在感。

## 2.8 铺开第一轮暴露的两个共享层缺陷（已修，记录以免重演）

这两条都不是代理写错，而是**共享层默认值选错**，两边独立撞上同一问题即是证据。

**① `.fx-body` 默认绝对定位 → 内容撑高的卡塌成 0 高。**
原默认 `position: absolute; inset: var(--fx-w)` 要求父级有确定高度。全站 10 个面里只有首页轮播是定高的，
其余 9 个都由内容撑高，用绝对定位会让卡内唯一子元素脱离文档流、卡片高度归零——
**整块内容消失且不报任何错**。接入的 9 个页面被迫各自手写覆盖，其中 4 页用 `margin: var(--fx-w)`、
5 页用 `.fx-card { padding: var(--fx-w) }`，两套并存时会叠成 8rpx 双重内缩。

修法是**把默认值反过来**：`.fx-card { padding: var(--fx-w) }` + `.fx-body { position: relative }`，
定高卡显式挂 `.fx-card--fill`。选流式做默认是因为两者失败模式不对称：
绝对定位错配 = 内容静默消失；流式错配 = 多出一圈可见内边距。**默认值要挑那个错了能看见的。**

**② `translate(-50%, -50%)` 只写在 `@keyframes fx-spin` 里 → 静态描边偏心。**
不挂 animation 的实例（所有列表项、以及降级后的卡）方块左上角停在卡片中心，
**只画得出右下两条边**。已在 `.fx-ring-spin` 基样式补上同一条 transform，关键帧里保留。

推论：**任何只在动画帧里出现的属性，都必须同时存在于基样式**，否则静态/降级态就是坏的。

**结论修正（铺开第一轮实测反馈驱动）**：原方案"列表项只上静态渐变描边"是不成立的，
因为 **conic 的颜色只随角度变化，而列表卡普遍扁宽**（activity 702×244、campus-service 648×108）。
上边缘相对方块中心只张约 ±10°，下边缘同理 → **两条长边各自几乎是同一个纯色**，
左右短边又最不明显。静态整圈读起来就是一条普通边框，看不出是渐变扫光。
加厚加亮都治不了，这是几何问题不是参数问题。

采用文中原本预留的备选方案：**列表项挂 `.is-entry`，进场转一圈后停住**
（`animation-iteration-count: 1`，1.4s）。有运动就有存在感，播完即停不留常驻开销。

⚠️ **必须按 index 限量**：`{{index < 6 ? 'is-entry' : ''}}`。
一屏十几张同时起转，瞬时合成开销会反超首页单卡。护栏测试会检查这一条限量写法是否存在。

## 3. 降级开关 `utils/motion.js`

全站此前 `prefers-reduced-motion` 与低端机判定命中数均为 0。铺到 10 个面之后这不再是可选项。

- **实现期收窄**：原设计是三态 `auto/off/on`，落地改成**布尔开关（默认开）+ 低端机强制关闭**。
  理由：设置页的开关组件是 `<switch>`，三态要额外造 UI；而"auto"的实质就是低端机判定，
  直接做成不可用户覆盖的强制关闭更简单，也更少一个能配错的东西。
- 偏好键 `cardFx_by_user`，沿用 `utils/hot-rank.js:6` 那套按用户 id 隔离的 map 读写写法。
- 低端机判定读 `wx.getDeviceInfo().benchmarkLevel`：有效值（≠ -1）且 < 25。
  **iOS 恒为 -1（取不到）**，未知按跑得动处理，只认明确的低分。
- `card-fx.wxss` 内再叠一条 `@media (prefers-reduced-motion: reduce)`，作为 OS 级免 JS 兜底。
- 命中降级时挂 `.fx-off`：`animation: none`，**只留静态描边、不留空白**。降级不能把效果降成"什么都没有"。
- 设置页新增「显示 → 卡片动效」switch，复用 `pages/settings/index.js` 的 `{ key, icon, name }` 数组模式
  与 `dailyHot` 的独立存储分支写法。

### 3.1 给设置页加 require 会打断的测试（已踩，记录以免重演）

`server/tests/` 里有 4 个测试用**手工模块桩 + vm** 加载 `pages/settings/index.js`：
`daily-hot-pref`、`settings-notify-channels`、`settings-publish-privacy`、`subscribe-binding-audit`、
`top-subscribe-entries`。给设置页新增任何 `require`，这些桩表就会抛
「测试桩未覆盖的模块」，且**报错发生在既有失败之前，会把原本的红因换成新的红因**，
看起来像回归。本轮已在 3 个桩表里补 `utils/motion`。
下次给设置页/首页加依赖时，先跑：
`for f in server/tests/*.test.js; do node "$f" 2>&1 | grep -q "未覆盖的模块：<新模块>" && echo $f; done`

## 4. 首页迁移与测试契约变更

- `pages/index/index.wxss` 顶部 `@import "../../styles/card-fx.wxss"`；
  `.banner-ring` / `.banner-ring-spin` / `.banner-face` / `.banner-glow*` 改指 `.fx-*` 类。
- **倾斜、光斑、流光（`.banner-spot` / `.banner-shine` / `buildTiltStyle` / `bannerTiltStyle`）留在首页不动。**
- ⚠️ 唯一的接口变更：`home-banner-press.test.js` 读的是 `pages/index/index.wxss` **原文**，
  `@import` 不会被解析。描边/背光那批断言必须改为读 `styles/card-fx.wxss`，否则会假红。
  倾斜/光斑那批断言仍留在 `index.wxss`。

## 5. 分波与文件归属

波内并行、波间串行。同一波内代理之间文件不相交。

| 波 | 内容 | 归属 |
|---|---|---|
| Wave 0 | 共享层 + `utils/motion.js` + 设置页开关 + 首页迁移 + 测试契约更新 | **串行**，后续全部依赖 |
| Wave 1 | wallet `.balance-card`、pkg-admin `.hero`、hot-rank `.hot-poster-wrap`、driving-school `.promo` | 可并行 |
| Wave 2 | club `.club-card`、group-chat `.gc-card`、activity `.act-card`、campus-service `.card-entry` | 可并行 |
| Wave 3 | 首页 `.today-hot-card`（仅背光） | 排在 Wave 0 之后，与首页文件冲突故单独成波 |

### 已确认的具体冲突与决定

- `.balance-card` 同时挂着 `app.wxss` 里导航栏共用的 `gradient-nav`。
  描边只能加在新包的 `.fx-body` 上，**不得改 `gradient-nav`**。
- `.promo` / `.club-card` / `.gc-card` / `.act-card` / `.school-card` 已有 `hover-class` 按压反馈。
  本轮不做倾斜，所以不存在两套 3D 反馈打架；描边与 hover-class 可共存，hover-class 保留不动。
- `.today-hot-card` 内部已有竖向 swiper 在动，再加旋转描边会打架 → **只上背光**。
- `.school-card`（driving-school:102-106）与 `.promo` 同文件 → 归入 Wave 1 同一代理，不拆开。

## 6. 新增测试 `server/tests/card-fx-shared.test.js`

源码断言，风格与 `home-banner-press.test.js` 一致（这类接线漏了不报错、只是静默没效果）：

1. `styles/card-fx.wxss` 存在，含 `@keyframes` 自转、conic 前有 linear 兜底；
2. 剥除 CSS 注释后全文无 `filter: blur`（`backdrop-filter` 除外）；
3. `.fx-off` 降级规则存在且落在 `animation` 上；
4. 每个接入页的 `.wxss` 确实 `@import` 了共享层；
5. 每个接入页的 `.wxml` 确实出现 `.fx-ring-spin` 与 `.fx-body`；
6. 描边方块用百分比 padding（防有人改回写死 rpx）。

## 7. 验证方式与已知限制

- 每个 Wave 完成后跑 `node server/tests/card-fx-shared.test.js` 与 `home-banner-press.test.js`，
  以及该页相关既有测试；红的一律用 `git worktree` 拉 HEAD 对照，区分回归与既有失败。
- 编辑后必查 `git diff --stat`：本项目源文件为 CRLF，整文件转 LF 会让 diff 从几十行膨胀到几千行。
- **本地无小程序模拟器，无法验证渲染结果。** 静态描边/背光的观感、conic 在老内核的退化、
  低端机降级是否生效，均需开发者工具与真机确认。每波交付时附自查清单。
