# 液态标签指示条（Elastic Tab Indicator）清单与实现

> 日期：2026-09-30
> 范围：全站下划线型标签指示条
> 驱动器：`utils/liquid-tab.js`；共享样式：`app.wxss`（`.liquid-indicator` 系列）
> 关联文档：`docs/2026-09-30_按钮弹性按压反馈.md`（同款弹性贝塞尔曲线族）

## 1. 交互效果定义

| # | 需求 | 实现 |
|---|---|---|
| 1 | 前沿快速奔向目标 | 相位一 `rush`（0.1s）：前沿边以 `cubic-bezier(0.3, 0.9, 0.5, 1)`（强 ease-out）冲向目标 |
| 2 | 后沿延迟 6 帧跟随 | 相位二 `chase` 在 `PHASE1_MS=100ms`（≈6 帧 @60fps）后才启动 |
| 3 | 中途拉伸至 2 倍以上 | rush 阶段宽度被拉到「原宽 + 位移」——相邻等宽 tab 即 2 倍，跨格跳转远超 2 倍 |
| 4 | 末端轻微超调 | chase 用 `cubic-bezier(0.34, 1.42, 0.6, 1)`（y1 > 1），后沿轻微越过目标再回落 |
| 5 | left/width，禁 scaleX | 指示条全部样式只用 `left` + `width` 过渡，护栏测试禁止 `transform` 出现 |

## 2. 双相位模型（核心设计）

指示条有两个沿：**前沿**（移动方向朝向的那一边）和**后沿**（拖尾）。`left`/`width` 与两沿的关系：左沿 = `left`，右沿 = `left + width`。

**右移**（目标在右侧，前沿 = 右沿）：

```
相位一 rush:  left 不变，width → 目标右沿 − 当前左沿
              → 右沿（前沿）冲刺到位，左沿（后沿）原地不动，指示条拉伸
相位二 chase: left → 目标左沿，width → 目标宽（弹性贝塞尔）
              → 后沿追赶 + 宽度收回
```

**左移**：镜像（left 先冲到目标，width 拉到「当前右沿 − 目标左沿」，再收回）。

**为什么末端超调只出现在后沿**：chase 相位里 `left` 与 `width` 用同一条弹性曲线插值，而它们的增量恰好等量反号（左移距离 = 收缩量），所以 `left(t) + width(t)` 恒等于目标右沿 —— **前沿全程钉死在目标位置纹丝不动**，`left` 的超调前冲被 `width` 的反向超调精确抵消，肉眼看到的只有后沿轻微越过目标再弹回。这正是液态橡胶的物理直觉：前手先按住，后手弹一下才停。

关键数学：设位移 `d = 目标左沿 − 当前左沿`（右移为正），rush 宽度 = `原宽 + d`；chase 阶段 `left` 增量 `+d`、`width` 增量 `−d`，任意时刻 `t` 的右沿 = `目标右沿 + d·f(t) − d·f(t) = 目标右沿`（`f` 为归一化插值函数），恒等式对任意缓动成立。

## 3. 实现代码

### 3.1 共享样式（app.wxss，全局生效）

```css
.liquid-tab-track { position: relative; }

.liquid-indicator {
  position: absolute;
  bottom: 0; left: 0; width: 0;
  height: 6rpx;
  border-radius: 999rpx;
  background: var(--liquid-indicator-color, var(--primary, #315CFF));
  pointer-events: none;
}

/* 基础态无 transition：首次落位（snap）不播动画 */
.liquid-indicator--rush {
  transition:
    left 0.1s cubic-bezier(0.3, 0.9, 0.5, 1),
    width 0.1s cubic-bezier(0.3, 0.9, 0.5, 1);
}

.liquid-indicator--chase {
  transition:
    left 0.3s cubic-bezier(0.34, 1.42, 0.6, 1),
    width 0.3s cubic-bezier(0.34, 1.42, 0.6, 1);
}

@media (prefers-reduced-motion: reduce) {
  .liquid-indicator--rush, .liquid-indicator--chase { transition: none; }
}
```

### 3.3 页面接入（以 errand-order 为例）

```xml
<view class="top-tabs liquid-tab-track">
  <view class="top-tab {{activeTab === index ? 'active' : ''}}" ... bindtap="onTab">{{item}}</view>
  <view class="liquid-indicator {{liquidPhase}}" style="{{liquidStyle}}"></view>
</view>
```

```js
onLoad() {
  this.liquidTab = liquidTab.create(this, { track: '.top-tabs', items: '.top-tab', indicator: '.liquid-indicator' })
  wx.nextTick(() => this.liquidTab.snap(this.data.activeTab))  // 首次落位无动画
},
onTab(e) {
  this.setData({ activeTab: index })
  this.liquidTab.moveTo(index)   // 两相位液态动画
},
onUnload() { this.liquidTab.destroy() }
```

## 4. 接入清单

| # | 场景 | 页面 | track / items | 旧指示条处理 |
|---|---|---|---|---|
| 1 | 我的跑腿订单顶部 tab（2 格） | pages/errand-order | `.top-tabs` / `.top-tab` | 移除 `.top-tab.active::after` |
| 2 | 个人主页帖子/收藏 tab（2 格，首 tab 可条件隐藏） | pages/profile | `.profile-tabbar` / `.profile-tab` | 移除 `.profile-tab.active::after` |
| 3 | 我的消息中心 tab（6 格） | pages/my-messages | `.tabs` / `.tab` | 移除 `.tab.active` 的 `border-bottom` |
| 4 | 首页帖子分类栏（8 格，**横滚** scroll-x） | pages/index | `.category-list` / `.category-item` | 移除 `.category-item.active::after` |

**横滚栏的处理（首页）**：指示条放在滚动内容（`.category-list`）内随内容移动，横滚完全由用户手动——**不做自动滚入**（曾实现过 scroll-left 自动联动，按用户反馈移除：点分类时列表自动横滚干扰了手动浏览）。注意深链接进入屏幕外的分类（失物寻物/二手闲置入口）时，激活指示条可能在视野外，需用户自己横过去看。驱动器的 `measure()` 仍保留暴露，供未来需要滚入联动的页面使用。

**未纳入（有意排除）**：

| tab 栏 | 页面 | 原因 |
|---|---|---|
| 灰轨道白卡分段器 | pages/activity、pages/my-posts | 激活样式是"卡片"而非"指示条"，滑动白卡若改液态需换视觉载体，属设计改版 |
| 胶囊底色 tab | pages/blacklist、pages/errand、pages/review/list | 同上；且 review/list 是 scroll-x 横滚栏，需要额外的 scroll-left 同步逻辑 |

这些页如需升级：给轨道加 `.liquid-tab-track`、插入指示条节点（颜色用 `--liquid-indicator-color` 调成半透明反色）、js 三行接线即可，驱动器与样式零改动。

## 5. 关键实现细节与优化点

1. **每页每次切换只有 2 次 setData**：相位间插值全部交给 CSS transition。逐帧 rAF/`setInterval` + setData 的过桥开销（序列化 + 渲染线程通信）在小程序里撑不住 60fps，护栏测试明确禁止。
2. **left/width 的回流成本可控**：指示条是 `position:absolute` 的小元素，其 layout 变化被限制在 `.liquid-tab-track`（relative）子树内，不影响页面其余布局；相比 scaleX（合成器 only 但会把圆角拉成椭圆），这是需求红线下的最优解。
3. **重测量只发生在挂载时**：几何缓存于驱动器实例，tab 集合不变则零测量开销；`refresh()` 供标签数量/可见性/窗口尺寸变化后手动触发（profile 页首 tab 条件隐藏即用例，数据序→渲染序换算见其 `liquidPos()`）。
4. **快速连点安全**：重入时清除相位定时器；CSS transition 被打断时从当前实时计算值重新插值（而非跳回起始值），连续切换不跳变。边界情况——在 chase 中途换目标：新 rush 从 live 位置冲刺，视觉连续。
5. **相位定时的渲染缓冲**：`PHASE1_BUFFER_MS=32` 补偿 setData 过桥的 1~2 帧延迟，避免 rush 尚未上屏就被 chase 类覆盖截断。
6. **首次落位不播动画**：没有"原位"可拉伸，snap 直接落位且基础态无 transition，避免页面进入时指示条从 0 宽飞出。
7. **减弱动效**：`prefers-reduced-motion` 下停掉过渡，指示条瞬间落位（状态仍可见）。
8. **测量单位即 px**：`boundingClientRect` 返回真机物理布局像素，内联样式直接写 px，各设备几何自动正确，无需 rpx 换算。
