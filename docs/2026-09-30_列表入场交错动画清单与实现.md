# 列表入场交错动画清单与实现

> 日期：2026-09-30
> 范围：全站内容型列表子项「入场交错动画」（stagger delay）
> 关联文档：`docs/2026-09-30_卡片动效共享层与全站铺开设计.md`（card-fx 共享层，本文复用其降级机制）

---

## 1. 效果定义

- **交错入场（stagger delay）**：列表子项按 `index` 顺序依次入场，步长 **60ms**。
- **单子项效果**：微弱弹性向上滑入 —— 自下方 `28rpx`、`scale 0.98` 处上滑落定，落定前**轻微越过终点再回弹**（约 4%~6% 过冲）。
- **参数**：时长 `0.45s`，缓动 `cubic-bezier(0.34, 1.3, 0.64, 1)`（y1 控制点 > 1 产生回弹；取 1.3 而非标准 back-out 的 1.56，避免一屏多卡同时入场时显得"蹦"）。
- **封顶规则**：`--i` 一律写 `{{index < 6 ? index : 0}}` —— 前 6 项按序错峰，第 7 项起延迟归零（多为滚动加载新增项，延迟 360ms+ 会显得迟钝）。
- **只动合成器属性**：关键帧只有 `transform` + `opacity`，不触碰布局属性，滚动中不引发重排。

## 2. 共享层实现（app.wxss，全局生效，页面无需 @import）

```css
.anim-stagger {
  animation: stagger-in 0.45s cubic-bezier(0.34, 1.3, 0.64, 1) both;
  animation-delay: calc(var(--i, 0) * 60ms);
}

@keyframes stagger-in {
  from { opacity: 0; transform: translateY(28rpx) scale(0.98); }
  to   { opacity: 1; transform: translateY(0) scale(1); }
}

.fx-off.anim-stagger { animation: none; }

@media (prefers-reduced-motion: reduce) {
  .anim-stagger { animation: none; }
}
```

页面接入两件事：

1. 子项 class 追加 `anim-stagger`；
2. 子项内联 style 写 `style="--i: {{index < 6 ? index : 0}};"`（已有内联 style 时合并写，如 club 卡的 `--fx-accent`）。

### 降级策略

| 情形 | 行为 | 机制 |
|---|---|---|
| 用户在设置里主动关动效 | 入场动画停，内容直接显示 | 页面已有的 `fx-off` class 命中 `.fx-off.anim-stagger` |
| 低端机（benchmark < 25） | 同上 | 同上（`motion.isCardFxOff()` 已在接入 card-fx 的页面生效） |
| 系统开启"减弱动态效果" | 同上 | `prefers-reduced-motion` 媒体查询 |
| 未接入 card-fx 的页面 | 仅有 OS 减弱动效兜底 | 该动画一次性、只动 transform/opacity，开销比 card-fx 常驻合成动画低一个量级，不做机型降级 |

### 与 card-fx 的叠加关系

活动卡 / 驾校卡 / 校园卡条目同时挂 `fx-card`（静态 conic 描边 + `is-entry` 进场转一圈）和 `anim-stagger`（上滑回弹）。两者是**不同元素上的不同 animation**（`fx-ring-spin` 在描边层、`stagger-in` 在卡本体），互不覆盖。

## 4. 排除场景及原因

| 页面 / 场景 | 排除原因 |
|---|---|
| pages/chat、pages/errand-chat 消息气泡流 | 消息持续追加渲染，非一次性入场；每条都播会持续闪动 |
| 首页轮播 banners、post-detail 侧边热榜 swiper | 轮播内交错无意义且与 swiper 自身动画叠加 |
| 各页 tab 栏、筛选 chips、表单选择行（gender-btn/type-btn/deadline-picker 等） | 表单控件，入场动画干扰操作感知 |
| 九宫格图片上传/预览、emoji 面板 | 预览类宫格，非内容流 |
| pages/schedule 课表 CSS Grid 表格 | 子项内联 style 全被 grid 定位占用（grid-row/grid-column），交错会破坏布局 |
| schedule-ocr 识别结果编辑卡 | 半表单（每项含输入行），入场动画与聚焦交互冲突 |
| errand-detail 订单记录弹层时间线 | 弹层内少量条目，优先级低，暂不接入 |
| pages/user 功能入口宫格 | 静态入口非内容流，且 hover 已有 fx-hover 反馈 |
| 各 tab 空态 empty-state | 单元素，无交错意义 |

## 5. 兼容性与性能

**兼容性**
- `calc(var(--i, 0) * 60ms)`：自定义属性 + calc 乘法是项目已上线范式（首页帖子流已生产验证）；iOS WKWebView 与安卓 X5/Chromium 现行内核均支持。
- `cubic-bezier` y1 > 1 的过冲回弹：标准 CSS Timing Function 能力，全部支持（不依赖 @property / Houdini，项目已验证该类特性在小程序 WebView 不可用，故未采用）。
- `prefers-reduced-motion`：与 card-fx 共享层同款兜底。
- `animation-fill-mode: backwards`：延迟期间子项保持 from 帧（透明+下移），入场前不闪烁。不能用 both——both 会把末帧 transform 永久钉在元素上，keyframes 的 transform 压过 transition，交错项同时是可按压元素时按压 scale(0.96) 将不生效（见《按钮弹性按压反馈》）。

**性能**
- 一次性动画（播完即停，无 `infinite` 常驻合成层），只动 `transform/opacity`，不触发重排/重绘。
- `--i` 封顶 6：同一时刻最多约 6 个动画实例错峰运行，瞬时合成开销有界。
- 分页加载的新增项延迟归零（`index < 6 ? index : 0` 的 0 分支），滚动加载不产生叠加延迟。
- 关键帧不加 `will-change`：一次性动画无需常驻提升图层。

## 6. 护栏测试

`server/tests/stagger-in-shared.test.js`（与 card-fx-shared.test.js 同款源码断言）：
- 锁定 `.anim-stagger` 必须用 `stagger-in` 关键帧 + 弹性曲线（y1 ∈ (1, 1.4)）；
- 关键帧属性白名单（只允许 transform/opacity）；
- 延迟必须走 `calc(var(--i, 0) * Nms)`；
- `.fx-off.anim-stagger` 与 `prefers-reduced-motion` 降级必须存在；
- 32 个接入页逐一断言已挂 `anim-stagger` 且 `--i` 已封顶。

## 7. 新页面接入规范（TL;DR）

```xml
<view class="xxx-card anim-stagger" style="--i: {{index < 6 ? index : 0}};" wx:for="{{list}}" wx:key="id">
```

- 子项是自定义组件时包一层 wrapper 再挂动画类；
- 已有内联 style 时把 `--i` 合并进去，不要写第二个 style 属性；
- 已接入 card-fx 的页面无需任何 JS 改动，fx-off 自动联动降级。
