# 小程序最终审核报告

审核日期：2026-08-25  
审核范围：微信小程序前端、Node.js/Express 服务端、数据库初始化/迁移脚本、隐私与外链配置、现有自动化测试。

## 2. 已通过项

### 2.1 代码与自动化验证

- 递归 JavaScript 语法检查：135 个文件，0 个语法错误。
- 后端现有测试全部通过：smoke、protocol、request-contract、payment-v3、admin-permissions、feature-flag，退出码均为 0。
- API 响应统一为 `code/message/data/requestId`；请求超时、401、只读请求重试、幂等键、限流和错误处理中间件均已实现。
- 内容安全中间件覆盖帖子、评论、私信、跑腿、反馈、资料等文本写入；图片上传在返回 URL 前执行图片安全检查，生产环境检测不可用时拒绝写入。
- 服务端支付回调包含时间戳、签名校验和 AES-GCM 解密实现；支付接口测试通过，但未完成真实商户联调。
- `web-view` 页面只接受 `https://` 链接；前端请求基础 URL 使用 HTTPS，WebSocket URL 可派生为 WSS。

### 2.2 数据库脚本

- `init.sql` 与迁移脚本覆盖用户、帖子、评论、课程、跑腿、维修、消息、反馈、注销、支付、钱包、管理员审计等业务表。
- 关键状态字段使用 ENUM/TINYINT/DECIMAL/JSON，订单号、支付流水号、钱包引用等关键字段有唯一索引或复合索引。
- 迁移脚本包含缺失列/索引的幂等补齐逻辑。

## 3. 阻断项与整改要求

### P0：必须在再次提审前关闭

1. **真实后端不可证明可用。** 前端已改为仅开发环境使用 Mock，体验版/正式版走真实 API；但 MySQL/Redis 服务未在本地运行，必须在类生产环境执行接口回归并保存请求/响应、数据库写入和回调证据。
2. **密钥已从工作区配置移除，但尚未完成轮换。** 根目录 `.env` 与 `server/.env` 已替换为占位配置并补充 `.env.example`，部署脚本改为读取环境变量，工作区中的上传/支付私钥文件已删除；原先暴露过的微信、数据库、JWT、支付密钥仍必须在微信/云主机/商户平台全部吊销轮换，并清理 Git 历史。
3. **支付和钱包属于高风险功能。** 维修支付、跑腿支付、退款、钱包提现涉及真实资金；必须先完成商户号/证书/平台公钥、回调 HTTPS、金额校验、退款/提现审核、对账、异常补偿和管理员通知验收。未完成前应在正式包隐藏/关闭钱包与支付入口。

### P1：必须整改后再提审

1. **隐私授权代码已补强。** `app.js` 现在统一保护定位、选址、媒体和保存相册 API，协议同意会调用 `wx.requirePrivacyAuthorize`；仍必须在微信后台完成指引配置并做真机同意/拒绝/撤回测试。
2. **隐私政策已更新。** 页面日期、第三方处理者、设备日志范围和注销冷静期已更新；仍需将相同内容同步到微信后台用户隐私保护指引。
4. **外部服务和跳转依赖后台白名单/授权。** 代码访问超星 H5、720 全景、教务系统，并跳转 5 个外部小程序 AppID。必须逐一确认业务域名、request/download/upload 合法域名、TLS 证书、`navigateToMiniProgramAppIdList` 授权和页面可用性；删除未授权或无法稳定打开的入口。小程序首页服务类目、简介和实际功能也需保持一致。
5. **上传存储已改为生产 fail-closed。** 生产环境不再暴露本地 `/uploads`，图片上传在对象存储适配器接入前返回 503，避免返回不可访问的假 URL；需完成对象存储适配器后再开放图片发布。
6. **内容审核覆盖已补强。** 课程 OCR 图片现在也经过图片安全检查；生产环境无真实 OCR 时不再返回演示课程；帖子举报已写入 `content_report` 并提供管理员查询/处理接口。视频入口仍应保持关闭，或接入 `media_check_async` 后再开放。

### P2：上线前完善

- 课程 OCR 无有效识别结果时已统一返回明确失败，正式环境仍需接入真实 OCR 引擎并对低置信度结果要求用户确认。
- 真实环境应将幂等缓存从进程内 Map 迁移到 Redis，避免多实例重复写入。
- 完成 iOS/Android 真机、弱网、长文本、键盘/安全区、图片失败、401、WebSocket 重连和冷/热启动性能测试，并保留 P50/P95 数据。
- `app.json` 页面/服务文字目前含中英文混用（Home、Schedule、Errand、Profile），应与小程序主体中文定位和提审简介统一，检查图标、标题、字号、空状态和无障碍细节。

## 4. 数据库检查结论

### 已确认

- 初始化和迁移脚本覆盖主要业务实体、状态枚举、唯一键和查询索引。
- 帖子/评论/点赞/收藏/分享统计有 seed 更新语句；支付交易、退款、钱包流水和提现有独立账表。

### 未完成（不能宣称通过）

- 无法连接当前配置的 MySQL 主机，未执行表结构落库、字段类型校验、约束校验、种子数据外键一致性、NULL/异常值扫描、备份恢复和慢查询验证。
- `server/.env` 使用远程 MySQL 与开发环境密码，根目录 `.env` 又使用另一套数据库名，配置存在漂移风险。必须统一单一部署配置并执行迁移校验。
- SQL 主要依赖应用层关联，未见全面外键约束；上线前应确认删除策略、孤儿记录扫描和事务边界。

## 5. 必须执行的复测清单

1. 轮换全部密钥并扫描 Git 历史；设置生产 `NODE_ENV=production`、强 JWT、真实微信/支付/数据库/Redis 配置。
2. 关闭 Mock，执行登录、资料、发帖/图片、评论/私信、课程/OCR、跑腿支付、维修支付、反馈、注销、管理员审核、退款/提现全链路。
3. 对每个写接口验证成功、重复提交、超时、401、权限不足、内容违规、图片违规和数据库回滚。
4. 执行数据库迁移、约束/索引检查、种子数据异常扫描、备份恢复演练和支付对账。
5. 在微信开发者工具和 iOS/Android 真机验证隐私授权、合法域名、H5、外部小程序跳转、WSS、定位/相册/手机号拒绝路径。
6. 仅当上述证据齐全、P0/P1 全部关闭后，再提交微信审核；提审版本必须是完整可用的生产功能，不得包含 Demo/Mock/占位支付。

## 6. 最终判定

**判定：不通过（P0 阻断）。** 现版本可作为开发/演示包，不能作为正式提审包。完成 P0 与 P1 整改并通过真实环境复测后，方可重新进行微信官方审核。
