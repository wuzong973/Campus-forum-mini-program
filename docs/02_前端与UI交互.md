## 一、视觉令牌与资源规范

来源：UI 重设计交付（2026-09 基线）。

### 背景

首页信息流、服务图标系统、课表网格、轮播图与个人资料等模块需要一套统一的设计语言。此前缺少集中定义的视觉令牌，颜色、圆角、动效散落在各页面，难以统一维护。

### 视觉令牌

| 令牌 | 值 |
| --- | --- |
| 主色 | `#315CFF` |
| 强调色 | `#12B8A6` |
| 暖色 | `#FF8A3D` |
| 背景色 | `#F4F6FA` |
| 卡片圆角 | `18rpx` |
| 动效 | `160ms` 按下反馈，`240-320ms` 过渡动画 |

### 资源规范

- **轮播图**：`assets/banners/banner-schedule.png`、`banner-community.png`、`banner-errand.png`，尺寸均 `750x400`，每张不超过 `10KB`。
- **服务图标**：`assets/icons/svc-*.png`，`48x48`，透明 PNG。
- **信息流操作图标**：`assets/icons/star.png`、`star-outline.png`、`more.png`。

### 实现说明

- 轮播图内容由 `utils/banner.js` 根据课表、帖子和服务上下文动态生成。
- 帖子卡片支持 1/2/3+ 图片布局以及乐观更新的点赞/收藏/关注状态。
- 发布支持图片/视频媒体选择、草稿持久化、加载状态、失败重试和首页信息流插入。

### 涉及文件

`assets/banners/*`、`assets/icons/*`、`utils/banner.js` 及首页/课表/个人资料页面。

### 验证

- 修改过的 JS 文件运行 `node --check`；`server` 中运行 `npm test`。
- 手动设备验证：微信开发者工具中检查 375px 手机、768px 平板和桌面模拟器宽度。

### 已知限制

## 二、布局铁律：fixed 元素与滚动容器

> 本节合并自 2026-09-10（导航栏滚动显隐）、2026-09-09（float-actions 下沉，由 09-10 文档转述）与 2026-09-15（评论面板 fixed 键盘）中关于 `position: fixed` 与滚动容器的重复踩坑，归并成一条完整铁律，不在各篇重复。

### 现象

首页多个原应「相对视口固定」的元素出现异常：

- 自定义导航栏整条消失且不恢复（2026-09-10）；
- 右下角浮动按钮整条沉到 tab 栏下（2026-09-09）；
- 评论面板 `position: fixed; bottom: 0` 弹键盘后输入区被遮挡（2026-09-15）。

### 根因（两条链）

**链路一：祖先元素的 `transform` 劫持 `position: fixed` 的包含块。**

- `app.wxss` 的 `.page-enter { animation: page-enter 0.28s var(--ease-standard) both; }` 使用 `animation-fill-mode: both`，动画结束后 `.page` 永久保留最后一帧 `transform: translateY(0)`。
- 只要元素存在非 `none` 的 `transform`，它就成为后代中 `position: fixed` 元素的**包含块**（containing block）。于是 `.custom-nav`、`.comment-sheet`、`post-card` 弹层、`.float-actions` 等退化为「相对 `.page` 定位」，并受 `.page { overflow: hidden }` 裁剪，不再是真正的「相对视口固定」。
- 2026-09-09 的 `.float-actions` 下沉即是此坑首次被踩，当时修法是把按钮移到 `.page` 外层，并留下教训「fixed 元素不要放在带入场动画（transform）的容器内」。2026-09-10 的 `.custom-nav`、仍在 `.page` 内的 `.comment-sheet`、`post-card` 弹层、`.campus-picker` 是同一坑的漏网之鱼。

**链路二：页面本体可被拖动，整页偏移无法复位。**

- `.page` 为 `min-height: 100vh`，内部 = 导航占位（`statusBarHeight + navBarHeight` ≈ 170rpx）+ 一个 `height: 100vh` 的 `scroll-view`，总高度比视口高出一个导航栏，因此页面本体（document）自身可被拖动约一个导航栏的高度。
- 用户滑到 `scroll-view` 顶部继续下拉时，手势链式滚到页面本体，被「固定」在 `.page` 顶部的导航栏跟着上移、整条移出屏幕；向上滚动只回滚内层 `scroll-view`，页面本体偏移不自动复位，下拉刷新与搜索栏刷新都只重置内层状态，导航栏再也回不来。

### 处理方案（布局铁律）

1. **fixed 元素必须脱离任何可能带 `transform` 的祖先**：`.custom-nav`、`.float-actions` 等放到 `.page` 外层；删除 `.page-enter` 的 `animation-fill-mode: both`，让 `.page` 不再永久保留 `transform`、不再劫持 fixed 包含块（keyframes 终态与元素默认样式一致，视觉等价）。
2. **滚动容器高度精确计算，让页面本体零滚动**：`.page { height: 100vh }`（原 `min-height`）；`.scroll-container { height: calc(100vh - var(--nav-h, 0px)) }`，占位 + scroll-view 恰好等于 100vh，任何手势都无法把整页顶上去；保留 `height: 100vh` 兜底行。`.page` 内联注入 `--nav-h: {{statusBarHeight + navBarHeight}}px`。
3. **fixed 底部面板需自行处理键盘高度**：评论面板等 `position: fixed; bottom: 0` 元素，输入框应监听键盘高度并上移面板，否则即使不自动聚焦，用户手点输入时键盘仍会盖住输入区（详见 §九）。

### 涉及文件

`app.wxss`（`.page-enter` / `.page`）、`pages/index/index.wxml`（`.custom-nav` 移外层、注入 `--nav-h`）、`pages/index/index.wxss`（`.scroll-container` 高度）、`pages/index/index.js`、`custom-tab-bar/index.js`、各 fixed 弹层组件。

### 验证

- 2026-09-10：新增 `server/tests/index-nav-scroll.test.js`，5 组 20+ 断言全通过；回归 `chat-back-to-post.test.js`、`smoke.test.js` 通过。
- 2026-09-15：新增 `server/tests/index-comment-sheet-keyboard.test.js` 等。
- 删除 `.page-enter` 的 `both` 后，`.page` 不再创建层叠上下文，`.page` 内 `z-index: 1000+` 弹层现在正确盖住 `z-index: 90` 浮动按钮（属修正）；首页 z-index 复核：导航 100、评论面板 210/220、banner 指示器 2，层级关系不变。

### 结论

首页 fixed 元素的「相对视口固定」必须由「脱离 transform 祖先 + 滚动容器精确高度 + 页面本体零滚动」共同保证；底部 fixed 面板的键盘避让由页面自己实现。其余带 `page-enter` 的页面（club/group-chat/activity）其 fixed 元素早已按约定放 `.page` 外层，本次改动对它们只有正向收益。

## 三、动效共享层公共约定

> **本节是 §四~§七 四套动效的共同底座。** 原先这四条约定在 4 篇文档里各写一遍，现统一在此表述，各节只保留该效果特有的参数。

### 3.1 弹性贝塞尔曲线族

四套动效共用同一族曲线，取值互相呼应：

| 用途 | 曲线 | 说明 |
| --- | --- | --- |
| **快进/冲刺** | `cubic-bezier(0.3, 0.9, 0.5, 1)` | 强 ease-out，用于按压压缩（0.12s）与液态指示条前沿冲刺（0.1s） |
| **回弹/落定** | `cubic-bezier(0.34, 1.42, 0.6, 1)` | `y1 > 1` 产生超调回弹；用于按压释放、液态指示条后沿追赶 |
| **入场回弹** | `cubic-bezier(0.34, 1.3, 0.64, 1)` | 同上但 `y1` 收窄到 1.3（见下） |

**为什么入场动画的 `y1` 比按压更保守（1.3 而非 1.42）**：交错入场时一屏可能同时有 6 张卡在动，1.56（标准 back-out）会显得「蹦」；按压是单元素瞬时反馈，1.42 更"弹"也不刺眼。

**护栏统一锁定**：回弹类曲线 `y1 ∈ (1, 1.45]`，入场类 `y1 ∈ (1, 1.4)`。

### 3.2 `animation-fill-mode` 必须用 `backwards`，不能用 `both`

这是交错入场与按压反馈**共用同一条铁律**（两个功能分别踩到、互相印证）：

- `both` 会把**末帧 `transform` 永久钉在元素上**；keyframes 里的 `transform` 会**压过 transition**。
- 后果：交错入场的子项如果同时是可按压元素，按压的 `scale(0.96)` 将完全不生效。
- 改 `backwards`：延迟期间保持 from 帧（透明 + 下移）不闪烁，落定后不再残留 transform。末帧与元素自然态一致，**视觉无差异**。

> 护栏 `press-spring-shared.test.js` 专门有一条断言：`.anim-stagger` 必须用 `backwards`（防回归）。

### 3.3 降级兜底：三层

四套动效都必须具备，缺一不可：

| 层 | 触发条件 | 机制 |
| --- | --- | --- |
| **用户主动关闭** | 设置页「显示 → 卡片动效」switch 关 | 页面已有的 `.fx-off` class → `animation: none` / `transition: none` |
| **低端机强制关闭** | `wx.getDeviceInfo().benchmarkLevel` 有效（≠ `-1`）且 `< 25` | `utils/motion.js` 判定，**不可被用户覆盖** |
| **系统减弱动态效果** | OS 级 `prefers-reduced-motion: reduce` | CSS 媒体查询（免 JS 兜底） |

**降级的底线：只留静态效果，不留空白。** 例如 card-fx 降级后仍有静态描边，而不是"什么都没有"。

**iOS 恒为 `-1`（取不到 benchmarkLevel）** → 未知按「跑得动」处理，只认明确的低分。

### 3.4 护栏测试的统一写法

四套动效的护栏测试（`card-fx-shared` / `stagger-in-shared` / `press-spring-shared` / `liquid-tab-shared`）都是**源码字符串断言**，风格一致，理由也一致：

> 这类「接线漏了不报错、只是静默没效果」的改动，必须有静态断言兜底。

统一断言模式：
1. 共享层的曲线参数落在护栏锁定的区间内；
2. 关键帧属性**白名单**（只允许 `transform` / `opacity`）；
3. 降级规则（`.fx-off` + `prefers-reduced-motion`）必须存在；
4. 每个接入页逐一断言「类名已挂 + 内联 style 已写」；
5. 禁止项（如禁止 `transform` 出现在液态指示条、禁止 `filter: blur` 出现在 card-fx）。

### 3.5 性能红线（四套共用）

- **只动合成器属性**：`transform` / `opacity`。`box-shadow` 过渡是重绘级（非重排），可接受但半径要小。
- **不加 `will-change`**：这四套都是**一次性或瞬时**动效，常驻提升图层反而浪费内存。
- **一屏并发数必须有界**：交错入场封顶 6（见 §5）、card-fx 列表项按 `index < 6` 限量（见 §4.8）。
- **禁止逐帧 `setData`**：液态指示条明确禁止 rAF / `setInterval` 逐帧驱动（过桥开销撑不住 60fps）。

## 四、卡片动效共享层 `card-fx`

来源：2026-09-30。范围：把首页轮播已落地的「旋转描边 + 呼吸弥散背光」抽成共享层，铺到全站 10 个面（其中 9 面拿描边），并补齐全站缺失的动效降级开关。**列表项只拿静态描边，自转保留给单实例主卡**（见 §4.7）。**本轮不含 3D 倾斜跟随**——倾斜、触点光斑、流光带继续只留在首页轮播。

### 4.1 背景

首页轮播（`pages/index/`）已单独实现这套效果并配了护栏测试 `server/tests/home-banner-press.test.js`。直接逐页复制内联被否决，理由有两条实证：

- `app.wxss:290` 那段注释记录过「同一元素分页写，就是怎么调都对不齐的根因」；
- 首页的描边方块写死 820rpx，是因为轮播卡尺寸已知（710×266，对角线 758）。其余面的高度各不相同（`.hot-poster` 还是 `mode="widthFix"` 的自适应图），抄数值必然在某个面上露缺口。

### 4.2 共享层 `styles/card-fx.wxss`

**结构**

```
.fx-stage                     承载背光。背光不能被裁，必须是卡片的兄弟节点
  .fx-glow-layer
    .fx-glow(.is-on)          交叉淡入：走 transition: opacity
      .fx-glow-pulse          呼吸脉动：走 animation，两者分开以免互相覆盖
  .fx-card                    卡片容器（position: relative，自身不裁切）
    .fx-ring                  圆角裁切层（overflow: hidden）
      .fx-ring-spin           自转方块，铺静态 conic-gradient
    .fx-body                  内容层，四边内缩 var(--fx-w)，露出的那一圈即描边
```

**实例 token（内联 style 传）**

| token | 含义 | 默认 |
| --- | --- | --- |
| `--fx-accent` | 主色，描边与背光共用 | `#4A7AFF` |
| `--fx-w` | 描边宽度 | `4rpx` |
| `--fx-r` | 卡片外圆角 | `24rpx` |
| `--fx-bleed` | 背光下溢量 | `56rpx` |
| `--fx-side` | 描边方块边长；仅在卡片比例超出 §4.3 不变式时显式给 | 空（走 170% padding） |

`.fx-body` 的圆角由 `calc(var(--fx-r) - var(--fx-w))` 推出，不单独传，避免内外圆角不同心。

### 4.3 几何不变式（本轮最关键的一条）

`.fx-ring-spin` 用百分比 padding 强制正方形，绕开"每页要知道自己对角线"的问题：

```css
.fx-ring-spin {
  position: absolute;
  left: 50%; top: 50%;
  width: 170%; height: 0; padding-bottom: 170%;
  transform: translate(-50%, -50%) rotate(0deg);
}
```

百分比 padding 相对**包含块宽度**解析，所以边长恒为卡宽 ×1.7，与卡高无关。

> **成立条件：卡高 ≤ 卡宽 × 1.63。** 超出该比例时方块盖不住对角线，旋转会在角上露缺口。接入每一面前先核对该比例；不满足的面改用 `--fx-side` 显式给边长。

### 4.4 描边动画

- conic 角度无法直接补间（小程序 WebView 不支持 `@property` / Houdini），**转的是方块元素本身**。
- `background` 先写 `linear-gradient` 兜底、再写 `conic-gradient` 覆盖：不支持 conic 的内核退化为静态渐变边，而不是整圈无边框。
- 只在 `.is-live` 的实例上播放（`animation` 挂在 `.is-live .fx-ring-spin`），非可见实例连动画都不挂载，而不是 paused。
- 周期 4.5s。慢于 6s 时任一时刻近似纯色，读不出"在转"。

### 4.5 背光

- 用多档 `radial-gradient` 模拟弥散，**禁止 `filter: blur()`**。首页是长列表 + 九宫格图 + video 的主滚动面，常驻逐帧模糊掉帧明显，视觉却等价。护栏测试剥注释后扫描。
- 亮芯落在卡面下沿上，图层一半高度藏在卡片后面，只有下溢部分可见。下溢量 `--fx-bleed` 默认 56rpx。
- **接入前必须确认该面下方有 ≥24rpx 空隙**，否则背光会被下一个元素盖住。首页是靠把 `.banner-indicator` 下边距 18→44rpx 腾出空间解决的；不是每个面都值得为它改布局。空隙不足的面**只上描边、不上背光**。
- 背光层是 `z-index: 0` 的定位元素，而 `.fx-stage` 不构成 stacking context，会画在本应盖住它的普通流元素之上。下方紧邻元素需要 `position: relative; z-index: 1`（首页 `.notice-bar` 已这么处理）。**不要把背光压到 `z-index: -1`**，那会连页面底色一起垫到下面去。

### 4.6 内容高度守恒（首页踩过的坑）

描边是从 `.fx-body` 四周内缩"扣"出来的，等于内容区少了 `2 × --fx-w` 高。轮播文字块按 258rpx 排版，扣完剩 250rpx 就会顶到裁切线，把顶部标签切掉半截，**且不报任何错**。

解法：容器高度由外层加回来，不从内容区出。共享层保留不变式断言：`容器高 - 2×描边宽 >= 内容设计高度`。

### 4.7 列表项不旋转（本轮的性能红线）

`.club-card` / `.gc-card` / `.act-card` / `.card-entry` / `.school-card` 全都在 `wx:for` 里，是列表项。每个列表项挂一个无限自转的 conic 合成层，滚动时是 N 层同时在转——这比首页单卡严重一个量级。

**决定：列表项只上静态渐变描边（`.fx-ring-spin` 不挂 animation），自转保留给单实例主卡**（首页轮播、`.balance-card`、`.hero`、`.hot-poster`、`.promo`）。

### 4.8 铺开第一轮暴露的两个共享层缺陷（已修，记录以免重演）

这两条都不是代理写错，而是**共享层默认值选错**，两边独立撞上同一问题即是证据。

**① `.fx-body` 默认绝对定位 → 内容撑高的卡塌成 0 高。**

原默认 `position: absolute; inset: var(--fx-w)` 要求父级有确定高度。全站 10 个面里只有首页轮播是定高的，其余 9 个都由内容撑高，用绝对定位会让卡内唯一子元素脱离文档流、卡片高度归零——**整块内容消失且不报任何错**。接入的 9 个页面被迫各自手写覆盖，其中 4 页用 `margin: var(--fx-w)`、5 页用 `.fx-card { padding: var(--fx-w) }`，两套并存时会叠成 8rpx 双重内缩。

修法是**把默认值反过来**：`.fx-card { padding: var(--fx-w) }` + `.fx-body { position: relative }`，定高卡显式挂 `.fx-card--fill`。

> **选流式做默认是因为两者失败模式不对称**：绝对定位错配 = 内容静默消失；流式错配 = 多出一圈可见内边距。**默认值要挑那个错了能看见的。**

**② `translate(-50%, -50%)` 只写在 `@keyframes fx-spin` 里 → 静态描边偏心。**

不挂 animation 的实例（所有列表项、以及降级后的卡）方块左上角停在卡片中心，**只画得出右下两条边**。已在 `.fx-ring-spin` 基样式补上同一条 transform，关键帧里保留。

> **推论：任何只在动画帧里出现的属性，都必须同时存在于基样式**，否则静态/降级态就是坏的。

**结论修正（铺开第一轮实测反馈驱动）**：原方案"列表项只上静态渐变描边"是不成立的，因为 **conic 的颜色只随角度变化，而列表卡普遍扁宽**（activity 702×244、campus-service 648×108）。上边缘相对方块中心只张约 ±10°，下边缘同理 → **两条长边各自几乎是同一个纯色**，左右短边又最不明显。静态整圈读起来就是一条普通边框，看不出是渐变扫光。加厚加亮都治不了，**这是几何问题不是参数问题**。

采用原本预留的备选方案：**列表项挂 `.is-entry`，进场转一圈后停住**（`animation-iteration-count: 1`，1.4s）。有运动就有存在感，播完即停不留常驻开销。

> ⚠️ **必须按 index 限量**：`{{index < 6 ? 'is-entry' : ''}}`。一屏十几张同时起转，瞬时合成开销会反超首页单卡。护栏测试会检查这一条限量写法是否存在。

### 4.9 降级开关 `utils/motion.js`

全站此前 `prefers-reduced-motion` 与低端机判定命中数均为 0。铺到 10 个面之后这不再是可选项。

- **实现期收窄**：原设计是三态 `auto/off/on`，落地改成**布尔开关（默认开）+ 低端机强制关闭**。理由：设置页的开关组件是 `<switch>`，三态要额外造 UI；而"auto"的实质就是低端机判定，直接做成不可用户覆盖的强制关闭更简单，也更少一个能配错的东西。
- 偏好键 `cardFx_by_user`，沿用 `utils/hot-rank.js:6` 那套按用户 id 隔离的 map 读写写法。
- 低端机判定读 `wx.getDeviceInfo().benchmarkLevel`（判定细节见 §3.3）。

- 命中降级时挂 `.fx-off`：`animation: none`，**只留静态描边、不留空白**。
- 设置页新增「显示 → 卡片动效」switch，复用 `pages/settings/index.js` 的 `{ key, icon, name }` 数组模式与 `dailyHot` 的独立存储分支写法。

## 五、列表入场交错动画

来源：2026-09-30。范围：全站内容型列表子项「入场交错动画」（stagger delay）。

### 5.1 效果定义

- **交错入场（stagger delay）**：列表子项按 `index` 顺序依次入场，步长 **60ms**。
- **单子项效果**：微弱弹性向上滑入 —— 自下方 `28rpx`、`scale 0.98` 处上滑落定，落定前**轻微越过终点再回弹**（约 4%~6% 过冲）。
- **参数**：时长 `0.45s`，缓动 `cubic-bezier(0.34, 1.3, 0.64, 1)`（取值理由见 §3.1）。
- **封顶规则**：`--i` 一律写 `{{index < 6 ? index : 0}}` —— 前 6 项按序错峰，第 7 项起延迟归零（多为滚动加载新增项，延迟 360ms+ 会显得迟钝）。
- **只动合成器属性**：关键帧只有 `transform` + `opacity`，不触碰布局属性，滚动中不引发重排。

### 5.2 共享层实现（`app.wxss`，全局生效，页面无需 `@import`）

```css
.anim-stagger {
  animation: stagger-in 0.45s cubic-bezier(0.34, 1.3, 0.64, 1) backwards;
  animation-delay: calc(var(--i, 0) * 60ms);
}

@keyframes stagger-in {
  from { opacity: 0; transform: translateY(28rpx) scale(0.98); }
  to   { opacity: 1; transform: translateY(0) scale(1); }
}

.fx-off.anim-stagger { animation: none; }

@media (prefers-reduced-motion: reduce) {
  .anim-stagger { animation: none; }
}
```

> `fill-mode` 必须是 `backwards` 而非 `both`，理由见 §3.2（否则按压 `scale(0.96)` 失效）。

页面接入两件事：

1. 子项 class 追加 `anim-stagger`；
2. 子项内联 style 写 `style="--i: {{index < 6 ? index : 0}};"`（已有内联 style 时合并写，如 club 卡的 `--fx-accent`）。

### 5.3 降级策略

| 情形 | 行为 | 机制 |
| --- | --- | --- |
| 用户在设置里主动关动效 | 入场动画停，内容直接显示 | 页面已有的 `fx-off` class 命中 `.fx-off.anim-stagger` |
| 低端机（benchmark < 25） | 同上 | 同上（`motion.isCardFxOff()` 已在接入 card-fx 的页面生效） |
| 系统开启"减弱动态效果" | 同上 | `prefers-reduced-motion` 媒体查询 |
| 未接入 card-fx 的页面 | 仅有 OS 减弱动效兜底 | 该动画一次性、只动 transform/opacity，开销比 card-fx 常驻合成动画低一个量级，不做机型降级 |

### 5.4 与 card-fx 的叠加关系

活动卡 / 驾校卡 / 校园卡条目同时挂 `fx-card`（静态 conic 描边 + `is-entry` 进场转一圈）和 `anim-stagger`（上滑回弹）。两者是**不同元素上的不同 animation**（`fx-ring-spin` 在描边层、`stagger-in` 在卡本体），互不覆盖。

## 六、按钮弹性按压反馈

来源：2026-09-30。范围：全站交互按钮/可点击元素的弹性按压触觉反馈。

### 6.1 效果定义

| 阶段 | 效果 | 实现 |
| --- | --- | --- |
| **按压**（touchstart / 鼠标按下） | `scale(0.96)` 物理压缩 + 深度内阴影（凹陷质感），0.12s 快速到位 | hover-class 按压类（`press-spring` 或页面自有 hover 类） |
| **释放**（touchend / touchcancel / 鼠标移出） | 回弹到原尺寸，带 **3%~5% 轻微超调**（spring overshoot），0.35s | 基础类 `spring-btn` 的弹性贝塞尔 transition |

- 压缩曲线：`cubic-bezier(0.3, 0.9, 0.5, 1)`（快进缓出）。
- 回弹曲线：`cubic-bezier(0.34, 1.42, 0.6, 1)`（取值理由与护栏区间见 §3.1）。
- 内阴影：`inset 0 2rpx 6rpx rgba(16,32,64,.16), inset 0 -1rpx 2rpx rgba(255,255,255,.08)` —— 上暗下亮模拟"按下去"的凹陷。

### 6.2 触发机制

用小程序原生的 **hover-class**（`view` / `button` / `navigator` 支持）：

- touchstart 加按压类、touchend/touchcancel/鼠标移出移除 —— 与 mousedown/touchstart、mouseup/mouseleave/touchend 时机一致；
- 开发者工具与 PC 端的鼠标点击同样触发，触摸/鼠标行为统一；
- 小程序视图无键盘焦点语义（无 tabindex/keyboard nav），键盘分支不适用，此为平台边界；
- 按压类统一追加 `hover-stay-time="80~120"`（原生默认 400ms 的松手滞留会把回弹拖住）。

### 6.3 共享层（`app.wxss`）

```css
.spring-btn {   /* 基础态：挂在交互元素 class 上 */
  transition:
    transform 0.35s cubic-bezier(0.34, 1.42, 0.6, 1),
    box-shadow 0.35s cubic-bezier(0.34, 1.42, 0.6, 1);
}

.press-spring { /* 按压态：hover-class 指向它 */
  transform: scale(0.96);
  box-shadow: inset 0 2rpx 6rpx rgba(16, 32, 64, 0.16), inset 0 -1rpx 2rpx rgba(255, 255, 255, 0.08);
  transition-duration: 0.12s;
  transition-timing-function: cubic-bezier(0.3, 0.9, 0.5, 1);
}

@media (prefers-reduced-motion: reduce) {
  .spring-btn, .press-spring { transition: none; }
}
```

释放时按压类被移除，元素回到基础态 —— 此时生效的是 `spring-btn` 的 0.35s 弹性贝塞尔，形成"快压慢弹"。

### 6.4 接入清单（规模）

| 接入项 | 数量 | 说明 |
| --- | --- | --- |
| 交互元素挂 `spring-btn` | **284** | 全部带 hover-class 的 view/button/navigator + 组件内按钮（post-card、service-grid、campus-picker） |
| hover-class 追加 `press-spring` | 280 | 其余 4 处为动态三元绑定（`: ''` 禁用分支），按压样式由注入的页面 hover 类承担 |
| hover 类注入按压样式 | 63 个类 | 各页自有 hover 类（`back-pill-hover`、`act-card--hover`、`chat-item-hover`…）统一补 `scale(0.96)` + 内阴影 |
| 原生 `<button>` 补接 hover-class | 136 | 此前完全没有按压反馈的提交/确认/返回按钮 |
| transition 合并 | 65 处 | 页面类自带 transition 会按级联顶掉 spring-btn，已把弹性段合并进原值（保留原有 bg/opacity 渐变） |

**覆盖范围边界**

- **纳入**：项目已标注交互反馈的所有元素（hover-class）+ 全部原生 button + 三个自定义组件内的可点元素。
- **未纳入**：只有 `bindtap` 而从未有按压反馈的内容卡（如部分设置行）——属产品交互行为变更，超出"按钮"范畴，需要时按 §6.7 两行挂法补接即可。

### 6.5 与既有设计的冲突处理

| 冲突点 | 处理 |
| --- | --- |
| 28 个 hover 类自带非规范 transform（0.82~0.99、translateY lift） | 统一到 `scale(0.96)`；lift-on-press（club-card / gc-card 上浮按压）整体改为按压压缩；原有 opacity/background/外阴影反馈保留 |
| 交错进场的 `animation-fill-mode: both` | 改为 `backwards`（理由见 §3.2） |
| `.row-pressed .action-icon` 等子元素图标动画（放大 1.14 等） | 保留——它们是按压时的子元素动效，与父级压缩叠加正是设计意图 |
| `.float-btn-top.show.float-btn-pressed` 复合选择器 | `translateY(0)` 为恒等复位，单独 `scale(0.96)` 完全等价 |

### 6.6 兼容性与性能

**兼容性**

- 全部使用 `transform` + `box-shadow` + `transition` 三项最基础的 CSS 能力，iOS WKWebView / 安卓 X5·Chromium 全支持；
- 不依赖 `:active`（小程序 WebView 不可靠）、不依赖 JS 事件（无监听开销、无状态同步问题）；
- `prefers-reduced-motion` 下停掉过渡，**保留瞬间 scale 状态变化**（减弱动效用户仍能看到按压发生了）。

**性能**

- `transform: scale` 走合成器；`box-shadow` 过渡是重绘级（非重排），inset 且模糊半径仅 6rpx，重绘面积小；
- transition 声明本身零开销——只在属性变化时生效，滚动/静止状态无任何计算；
- 不使用 `will-change`（理由见 §3.5）。

### 6.7 新按钮接入规范（TL;DR）

```xml
<button class="primary spring-btn" hover-class="press-spring" hover-stay-time="120">提交</button>

<!-- 方式二：页面已有 hover 类（wxss 里该类需含 scale(0.96) + inset 阴影） -->
<view class="xxx spring-btn" hover-class="xxx-hover press-spring" hover-stay-time="80">…</view>
```

## 七、液态标签指示条

来源：2026-09-30。范围：全站下划线型标签指示条。驱动器 `utils/liquid-tab.js`；共享样式 `app.wxss`（`.liquid-indicator` 系列）。

### 7.1 交互效果定义

| # | 需求 | 实现 |
| --- | --- | --- |
| 1 | 前沿快速奔向目标 | 相位一 `rush`（0.1s）：前沿边以 `cubic-bezier(0.3, 0.9, 0.5, 1)`（强 ease-out）冲向目标 |
| 2 | 后沿延迟 6 帧跟随 | 相位二 `chase` 在 `PHASE1_MS=100ms`（≈6 帧 @60fps）后才启动 |
| 3 | 中途拉伸至 2 倍以上 | rush 阶段宽度被拉到「原宽 + 位移」——相邻等宽 tab 即 2 倍，跨格跳转远超 2 倍 |
| 4 | 末端轻微超调 | chase 用 `cubic-bezier(0.34, 1.42, 0.6, 1)`（y1 > 1），后沿轻微越过目标再回落 |
| 5 | 只用 left/width，禁 scaleX | 指示条全部样式只用 `left` + `width` 过渡，护栏测试禁止 `transform` 出现 |

### 7.2 双相位模型（核心设计）

指示条有两个沿：**前沿**（移动方向朝向的那一边）和**后沿**（拖尾）。`left`/`width` 与两沿的关系：左沿 = `left`，右沿 = `left + width`。

**右移**（目标在右侧，前沿 = 右沿）：

```
相位一 rush:  left 不变，width → 目标右沿 − 当前左沿
              → 右沿（前沿）冲刺到位，左沿（后沿）原地不动，指示条拉伸
相位二 chase: left → 目标左沿，width → 目标宽（弹性贝塞尔）
              → 后沿追赶 + 宽度收回
```

**左移**：镜像（left 先冲到目标，width 拉到「当前右沿 − 目标左沿」，再收回）。

**为什么末端超调只出现在后沿**：chase 相位里 `left` 与 `width` 用同一条弹性曲线插值，而它们的增量恰好等量反号（左移距离 = 收缩量），所以 `left(t) + width(t)` 恒等于目标右沿 —— **前沿全程钉死在目标位置纹丝不动**，`left` 的超调前冲被 `width` 的反向超调精确抵消，肉眼看到的只有后沿轻微越过目标再弹回。这正是液态橡胶的物理直觉：前手先按住，后手弹一下才停。

**关键数学**：设位移 `d = 目标左沿 − 当前左沿`（右移为正），rush 宽度 = `原宽 + d`；chase 阶段 `left` 增量 `+d`、`width` 增量 `−d`，任意时刻 `t` 的右沿 = `目标右沿 + d·f(t) − d·f(t) = 目标右沿`（`f` 为归一化插值函数），**恒等式对任意缓动成立**。

### 7.5 关键实现细节与优化点

1. **每页每次切换只有 2 次 setData**：相位间插值全部交给 CSS transition。逐帧 rAF/`setInterval` + setData 的过桥开销（序列化 + 渲染线程通信）在小程序里撑不住 60fps，护栏测试明确禁止。
2. **left/width 的回流成本可控**：指示条是 `position:absolute` 的小元素，其 layout 变化被限制在 `.liquid-tab-track`（relative）子树内，不影响页面其余布局；相比 scaleX（合成器 only 但会把圆角拉成椭圆），这是需求红线下的最优解。
3. **重测量只发生在挂载时**：几何缓存于驱动器实例，tab 集合不变则零测量开销；`refresh()` 供标签数量/可见性/窗口尺寸变化后手动触发（profile 页首 tab 条件隐藏即用例，数据序→渲染序换算见其 `liquidPos()`）。
4. **快速连点安全**：重入时清除相位定时器；CSS transition 被打断时从当前实时计算值重新插值（而非跳回起始值），连续切换不跳变。边界情况——在 chase 中途换目标：新 rush 从 live 位置冲刺，视觉连续。
5. **相位定时的渲染缓冲**：`PHASE1_BUFFER_MS=32` 补偿 setData 过桥的 1~2 帧延迟，避免 rush 尚未上屏就被 chase 类覆盖截断。
6. **首次落位不播动画**：没有"原位"可拉伸，snap 直接落位且基础态无 transition，避免页面进入时指示条从 0 宽飞出。
7. **减弱动效**：`prefers-reduced-motion` 下停掉过渡，指示条瞬间落位（状态仍可见）。
8. **测量单位即 px**：`boundingClientRect` 返回真机物理布局像素，内联样式直接写 px，各设备几何自动正确，无需 rpx 换算。

## 八、导航栏滚动显隐

来源：2026-09-10 修复说明（与 §二 同根，本节聚焦显隐状态机本身）。

### 现象

首页向下滚动后，顶部自定义导航栏（品牌胶囊「广轻校园圈」+ 浅蓝渐变底）整条消失；向上滚回顶部、下拉刷新、点击搜索栏刷新按钮后，导航栏都不再出现；副症状为整页内容上移约一个导航栏高度（banner 顶部被裁、状态栏被深蓝占满）。

### 根因

见 §二「布局铁律」链路二：页面本体可被拖动，把伪固定的导航顶出屏幕且无法复位；叠加 `.page-enter` 残留 `transform` 使导航非真正 fixed。

### 处理方案

在布局铁律修好的基础上，把导航栏显隐做成显式状态机：

- `pages/index/index.js` 新增 `data.navVisible`；`onContentScroll` 按滚动方向驱动显隐；`onContentScrollToUpper` / `scrollContentToTop` / `onShow` / `onContentRefresh` / `onPullDownRefresh` / `onRefreshAction` 一律强制展开（任何「重新出现」入口都复位）。
- `.custom-nav` 增加 `transform/opacity` 过渡与 `.nav-hidden { transform: translateY(-100%); opacity: 0 }`。
- 显隐判定（`onContentScroll`）：

```js
const isAtTop = scrollTop < NAV_AT_TOP_OFFSET            // 8：已在顶部 → 必定展开
let navVisible = this.data.navVisible
if (isAtTop || delta <= -NAV_DIRECTION_THRESHOLD) navVisible = true        // 上滚 ≥6px → 展开
else if (delta >= NAV_DIRECTION_THRESHOLD && scrollTop > NAV_HIDE_MIN_OFFSET) navVisible = false  // 下滚 ≥6px 且离开顶部 30px → 收起
```

- 沿用 80ms 节流，只对变化的字段 `setData`；方向阈值 6px + 收起最小位移 30px，避免像素级抖动。

### 涉及文件

`pages/index/index.wxml`、`pages/index/index.wxss`（`.custom-nav` / `.nav-hidden`）、`pages/index/index.js`（状态机）、`app.wxss`（布局铁律部分）。

### 验证

`server/tests/index-nav-scroll.test.js` 覆盖 5 组共 20+ 断言全通过：向下收起→向上展开→再下滚收起→回顶保持展开；`bindscrolltoupper` 必展开；回顶部入口必展开；`onShow`/下拉刷新/搜索栏刷新必展开；80ms 节流内高频被忽略、低位移不抖动。回归 `chat-back-to-post.test.js`、`smoke.test.js` 均通过。

### 结论

导航栏显隐与布局铁律绑定解决：先保证导航真正 fixed 且页面零滚动，再用方向状态机驱动收起/展开，所有复位入口显式强制展开，杜绝「回不来」。

## 九、评论面板键盘行为

来源：2026-09-15 修复说明（键盘避让的布局部分亦并入 §二）。

### 现象

首页帖子列表点评论图标（「评论 9」）打开评论面板时，键盘自动弹出并遮住评论列表；用户意图是读评论而非写评论。

### 根因

1. **语义写错**：打开面板的语义被写成「准备发评论」。`onPostComment()` 直接 `setData({ commentSheetFocus: true })`，`focus` 是微信 `<input>`/`<textarea>` 受控属性，绑值变 `true` 即聚焦拉起键盘；`commentMode === "sheet"` 且页面为首页（全仓仅首页用 `sheet`，其余页用默认 `detail` 跳详情页带 `&comment=1`）。

## 十二、路由防重与 webviewId 报错

来源：2026-09-11 修复说明。

### 现象

控制台红色报错：`SystemError (appServiceSDKScriptError) "[Page Route 错误](system error)] routeDone with a webviewId 266 is not found"`。

- `custom-tab-bar/index.js` 的 `onChange`：点击当前已选中 tab 仍走 `wx.switchTab`，对当前页重复路由（经典触发源），且整页无意义重载。

### 处理方案

| 位置 | 修复 |
| --- | --- |
| `app.js` 新增 `installRouteGuards()`（onLaunch 首位调用） | 对 `navigateTo / redirectTo / reLaunch / switchTab` 统一加「进行中」锁：一条路由未结束前重复调用**静默忽略**（表现与原生一致「点了没反应」）；`success` 回调后 350ms 冷却覆盖转场动画窗口；**`fail` 立即放行**，保留「navigateTo 失败回退 switchTab」（首页公告链接跳 tab 页）链式跳转 |
| `custom-tab-bar/index.js` 的 `onChange` | 点击当前已选中 tab 直接 `return`，不再重复 `switchTab` |

### 涉及文件

### 验证

## 十四、二维码弹层放大态

### 现象

「联系管理员 / 添加微信」的二维码弹层（`components/contact-admin`，12 个页面在用；`pages/push-groups` 有一份同款实现）点「点击可放大」后，得到的是：**白底满屏 + 顶部标题被状态栏压住 + 底部露出自定义 tabbar 与页面内容**（2026-10-08 用户实测截图）。期望的是微信图片查看器那种观感：**深色满屏、只留二维码大图、零 UI**。

### 根因（三条叠加）

放大态原来只做了「居中卡片 → 铺满全屏」一件事（`.contact-admin-qr-dialog.is-expanded` / `.qr-dialog.is-expanded`）：

1. **底部露出 tabbar（两层原因叠加）** —— ① 面板只铺 `height: 100vh`，而 `position: fixed` 的包含块是「页面视口」、不含 tabbar（`custom-tab-bar/index.wxss` 里 `.tab-bar` 高 `104rpx + env(safe-area-inset-bottom)`，在页面流底部）→ 几何上就没盖到；② **即使把面板撑到 tabbar 之下也盖不住** —— 自定义 tabBar 由框架渲染在**页面内容之上**（官方推荐用 `cover-view` 以保证层级；本项目是普通 `view`，同样在页面之上），`z-index: 2001` 对它无效。**所以必须整块隐藏它**（见下）。
2. **标题栏没隐藏** —— 放大后仍渲染 `head`（标题 + 提示 + ×），且 `padding-top` 只有 `24rpx`（没算状态栏）→ 标题被状态栏/胶囊压住；提示文案还会随 `qrExpanded` 变成「点击可缩小」，与「放大」自相矛盾。
3. **底色仍是白色** —— 图片本身是白底二维码卡片，白底叠白底 → 看不出边界，四周一片空白。

### 处理方案

放大态改成「深色满屏查看器」，**放大仍留在页面内**（这条不能动，理由见下）：

- `wxml`：`head` 加 `wx:if="{{!qrExpanded}}"`（放大态整条标题栏不渲染）；遮罩挂 `is-zoom`。
- `wxss`：`.is-expanded` 用 `top:0; left:0; width:100vw` **显式铺满**（别用 `width:auto` 靠 `left/right` 拉伸），高度**分两行写**（标准 CSS 回退）——`height: 100vh` 兜底 + `height: calc(100vh + 104rpx + env(safe-area-inset-bottom))` 把面板往下多撑出 tabbar 的高度（靠 `z-index: 2001` 盖住它）；`background: #000`；`padding: calc(24rpx + env(safe-area-inset-top)) 0 calc(104rpx + env(safe-area-inset-bottom))` —— **底部那段 padding 必须把多撑的高度抵消掉**，否则图片是在「含 tabbar 的整块」里居中、整体偏下。
- `.is-full`（放大态的图片本身）：必须**显式覆盖基类的 `max-width: 560rpx`**（改 `max-width: none`），且 `margin` 要写成 `0 auto` —— 基类是 `margin: 24rpx auto 0`，那个 **`auto` 就是水平居中**，写成 `margin: 0` 会让图片靠左贴边。**两条都漏 → 图片宽度被卡在 ~400px 且贴左**（2026-10-08 用户报「没有居中」，实测 538px 屏宽下卡片只占 413px、偏左 63px）。
- `js`：`stopPropagation()` 在放大态收起（`this.setData({ qrExpanded: false })`）。放大态没有关闭按钮，「点弹层任意处」是唯一出口，对齐微信查看器的「点一下退出」。
- `custom-tab-bar`：data 加 `hidden: false`、根节点绑 `wx:if="{{!hidden}}"`；放大态由 `setTabBarHidden(true)` 通过**页面实例**的 `getTabBar()` 整块隐藏（**每个 tab 页的 tabBar 是独立实例**，非 tab 页 `getTabBar()` 返回 `undefined`，必须判空）。**恢复点必须齐全**：收起放大 / 关闭弹窗 / 页面 `hide` / 组件 `detached`（`pages/push-groups` 用 `onHide`）—— 漏一个 = 那个 tab 页的 tabBar 永久消失。

### ⚠ 为什么不直接用 `wx.previewImage`

2026-10-07 曾改成走 `wx.previewImage`，用户实测反馈「**放大后长按没菜单**」：`show-menu-by-longpress` 是页面里 `<image>` 的原生能力，注入不进微信自带查看器；且 previewImage 里再长按对**个人好友码根本识别不出**（微信限制）。故 2026-10-08 改回页面内放大。**护栏 `push-group-detail.test.js` ④ 组明确断言 JS 里不得出现 `previewImage`，勿改回。**

### 涉及文件

| 文件 | 改动 |

### ⚠ 两次端上回归（改这块之前先读）

1. **「点击后无法放大」** —— 放大态弹层整层绑了 `catchtap="stopPropagation"`（点任意处退出放大），图片若用 `bindtap="toggleQrZoom"` 会**冒泡**上去：刚放大就被同一层立刻收起，端上表现成「点了没反应」。**图片必须用 `catchtap`。**
2. **「弹窗变形错位」（宽度塌成窄条）** —— 试过用 `left:0; right:0; width:auto` 靠双向定位拉伸，小程序里实测会收缩；`height: calc(100% + …)` 也没兜底。**必须 `width:100vw` 显式铺满 + 高度两行回退（`100vh` 兜底，再 `calc(100vh + 104rpx + 安全区)` 增强）。**
3. **「底部永远露一条 tabbar」** —— 光把 `height` 撑出去不够：自定义 tabBar 渲染在页面内容之上，`z-index` 盖不住。**必须在放大态用 `setTabBarHidden(true)` 整块隐藏，并在所有出口恢复。**
4. **「放大后图片没有居中」（偏左）** —— `.is-full` 覆盖了基类的 `margin`（写成 `0`，把负责水平居中的 `auto` 一起干掉），又没覆盖基类的 `max-width: 560rpx` → 图片宽度卡在 ~400px 且贴左。**必须 `max-width: none` + `margin: 0 auto`。**

四条都已写进 ④b 组断言（含 tabBar 的 `wx:if` / `getTabBar` 判空 / 恢复点齐全 / `.is-full` 的 `max-width` 与 `margin`），改回去就红。

### 已知限制

- 多撑出的那一段靠 `z-index: 2001` 压住自定义 tabbar，前提是 tabbar 在页面流内（本项目如此）。**若 tabbar 高度改了（现为 `104rpx + 安全区`），`.is-expanded` 里的 `104rpx`（高度 calc 与底部 padding 两处）必须同步改。**
- Android 上 `env(safe-area-inset-top)` 恒为 0，状态栏留白比 iOS 少；因图片是居中显示，不会顶进状态栏。

## 十五、遗留问题与后续建议

1. **评论面板另一条路径未统一**：其余页（搜索结果/我的帖子/个人主页）用 `commentMode="detail"`，点评论跳详情页并在 450ms 后自动聚焦弹键盘，与首页「先看评论」语义不一致。若需统一，删掉 `pages/post-detail/index.js:128-131` 的 `setTimeout` 自动聚焦分支即可，建议产品确认是否故意。
2. **布局铁律需固化到规范**：fixed 元素脱离 transform 祖先 + 滚动容器精确高度 + 底部面板自处理键盘高度，建议写入团队组件开发规范，避免后续页面再次踩坑。
3. **占位入口治理持续化**：`isServiceAvailable` 与 `SERVICE_ROUTES` 已从源头拦截占位入口，新增服务需同步维护登记表与路由表，否则 `home-entry-availability.test.js` 会失败。
4. **动效的观感无法本地验证**：本地无小程序模拟器，静态描边/背光的观感、conic 在老内核的退化、低端机降级是否生效，均需开发者工具与真机确认。
5. **card-fx 列表项的观感备选**：列表项采用「进场转一圈后停住」（§4.8）。若仍觉得存在感不足，可评估是否提高 `--fx-w` 或换用更强的 `--fx-accent` 对比色。
6. **液态指示条的横滚联动**：首页分类栏刻意不做自动滚入（用户反馈干扰手动浏览）；深链接进入屏幕外分类时指示条可能在视野外。驱动器的 `measure()` 已保留暴露，供未来需要时启用。
7. **UI 重设计交付的 Figma 缺失**：当次交付未暴露 Figma MCP 工具，设计交付物为仓库资源+代码+文档形式，后续如需实时 Figma 协作需补接。
