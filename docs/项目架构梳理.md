# 项目架构梳理

## 1. 项目定位

该仓库是一个“微信小程序前端 + Node.js 后端 + MySQL 数据库 + 教务系统爬虫接入”的校园综合服务项目，当前承载四类核心能力：

1. 校园首页与服务导航
2. 课程表管理与教务系统同步
3. 社区论坛、评论、转发、收藏
4. 代拿跑腿与私信消息

当前仓库不是前后端分离到多仓模式，而是单仓维护：

- 小程序前端位于项目根目录
- 后端服务位于 `server`
- 教务系统爬虫位于 `教务系统爬虫`

## 2. 顶层目录结构


## 3. 技术架构总览

## 3.1 小程序前端

- 技术形态：原生微信小程序
- 主要文件组织：`pages + components + utils`
- 全局状态入口：`app.js`
- 请求封装：`utils/request.js`
- 业务 API：`utils/api.js`
- 登录态与用户态：`utils/auth.js`
- 课表数据标准化：`utils/schedule.js`

## 3.2 后端服务

- 技术栈：Node.js + Express + MySQL + JWT + WebSocket
- 入口：`server/app.js`
- 认证方式：Bearer Token
- 路由层：`server/routes/*.js`
- 控制器层：`server/controllers/*.js`
- 中间件：`server/middleware/*.js`
- 数据库迁移：`server/utils/migrations.js`

## 3.3 教务系统爬虫

- 技术栈：Node.js + axios + cookie jar + cheerio + tesseract.js
- 核心能力：
  - 教务系统登录
  - 验证码 OCR
  - 课表 HTML 抓取
  - 课表结构化解析
- 当前接入方式：
  - 不直接运行在小程序内
  - 由后端 `server/services/jwScheduleSyncService.js` 调用

## 6. 当前课表同步接入架构

本次接入后，课表同步链路已经统一到现有服务中，结构如下：

```text
pages/schedule/index
  -> pages/schedule-login/index
  -> utils/api.syncSchedule()
  -> POST /api/v1/schedule/sync
  -> server/controllers/scheduleController.sync
  -> server/services/jwScheduleSyncService.syncScheduleFromJw
  -> 教务系统爬虫/crawler.js
  -> 教务系统网页登录 / 课表抓取 / HTML 解析
  -> 写入 user_schedule
  -> 返回标准课程数组
  -> 小程序本地 storage: schedule_courses
```

## 7. 核心代码运行逻辑

## 7.1 小程序启动

`app.js` 在 `onLaunch` 中完成：

1. 登录过期检查
2. Token / userInfo / scheduleConfig 回填
3. WebSocket 初始化
4. 系统栏与胶囊位置信息计算

## 7.2 前端请求链

`utils/request.js` 负责：

1. 自动附加 `Authorization`
2. 统一处理 `401`
3. 统一超时控制
4. 统一错误提示

## 7.3 课表页渲染链

`pages/schedule/index.js` 当前运行逻辑：

1. 从全局配置计算当前周
2. 读取后端课表列表
3. 使用 `utils/schedule.normalizeCourse()` 标准化
4. 按 `startWeek / endWeek / weekType` 过滤当前周课程
5. 构建 Grid 数据并渲染周视图

## 7.4 教务同步链

`server/services/jwScheduleSyncService.js` 负责：

1. 构造爬虫实例
2. 执行登录与 OCR 验证码识别
3. 按学期周次批量抓取每周课表
4. 将每周课表聚合为“课程 + 周范围 + 单双周”标准结构
5. 返回给 `scheduleController` 入库

## 10. 当前架构结论

当前项目已经形成比较清晰的三层结构：

1. 小程序前端负责交互、状态展示与本地缓存
2. Node 后端负责身份校验、业务聚合与数据库持久化
3. 教务系统爬虫作为后端内部能力模块，专职处理外部系统登录与课表抓取

这意味着后续若继续扩展“成绩查询”“考试安排”“空教室查询”，可以直接沿用现有模式：

`小程序页面 -> server 路由/控制器 -> 爬虫适配服务 -> 教务系统`
