## 三、发现的问题

### 问题 1（高）未加白名单的环境下无法发帖，写接口全部 503
所在环节：服务端 -> 内容安全中间件 -> 微信开放接口

复现步骤：
1. cd server && PORT=3100 node app.js（.env 中 WX_APPID/WX_APPSECRET 为真实值）
2. 用任意有效 JWT 调用 POST /api/v1/post，body {"title":"t","content":"c"}
3. 返回 HTTP 503 code=503 服务器出口 IP 不在微信 API 白名单中，请在微信公众平台添加该 IP

根因：
- server/routes/postRoutes.js:18 发帖路由挂了 contentSecurity 中间件
- server/middleware/contentSecurity.js:37-44：appid 已配置就调 getAccessToken()
- server/utils/wechatToken.js:32：出口 IP 未加入微信公众平台 IP 白名单时抛 503
- 该 503 是 fail-closed（宁可不发也不放过未检测内容），行为正确，但完全阻断本地开发的发帖/评论/私信等写操作

影响范围：所有挂 contentSecurity 的写接口（发帖、评论、评价、私信、跑腿发布等）。
需要确认：线上 payun01.cn 的出口 IP 是否已在白名单（线上写接口需登录后实测）。
规避方式（仅开发环境）：以 WX_APPID=your_appid、WX_APPSECRET=your_appsecret 启动，configured() 返回 false，走「未配置则跳过检测」的开发豁免分支（contentSecurity.js:37-43）。

### 问题 2（高）业务数据几乎全空，核心页面只能显示空态
所在环节：数据库 / 运维数据

复现步骤：
1. 连 gqg_campus 库
2. SELECT COUNT(*) FROM forum_post; 结果为 0
3. 对 68 张表逐一 COUNT(*)，56 张为 0

影响：首页帖子流、帖子详情、活动、群聊、跑腿、驾校、评价、钱包、消息等全部只能显示空态；小程序能跑起来但没有内容可看。线上只读探测中 GET /club/detail/1、/group-chat/detail/1、/activity/detail/1、/review/target/1 均 404，与对应表无数据一致。
说明：本次核对的是本地开发库；线上库数据量需另行核对（/club/categories、/service/list 有返回，说明线上至少有基础字典数据）。

### 问题 3（提示）静态分析脚本假阳性
pkg-admin/utils/admin.js 使用包装函数 const get = (path) => request.get('/admin' + path, ...)，导致端点静态提取得到 /admin:id 形态。非产品缺陷，已在结论中排除。
