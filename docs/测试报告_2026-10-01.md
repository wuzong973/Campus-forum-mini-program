## 五、失败原因分析

### 5.1 `press-spring-shared.test.js`：新按钮未按共享层规范接入（真实产品缺陷）

**触发源**：`pages/post-publish/index.wxml:49`（本次未提交改动，该行 `git diff` 显示整行被替换）

```html
<!-- 新增：投票编辑器头部胶囊「添加」 -->
<view class="poll-editor-add spring-btn" hover-class="poll-editor-add-hover" hover-stay-time="80" bindtap="saveComponentEditor">添加</view>

<!-- 原（HEAD）：底部确认按钮，合规写法 -->
<button hover-class="press-spring" class="sheet-confirm spring-btn" bindtap="saveComponentEditor" hover-stay-time="120">保存投票</button>
```

**判定依据**：`docs/2026-09-30_按钮弹性按压反馈.md` §7 明确两种合规写法，其中「方式二：页面已有 hover 类」要求 `hover-class="xxx-hover press-spring"`，且该 hover 类在 wxss 中必须含 `scale(0.96)` + inset 内阴影。

**实际状态**：

- WXML 侧：`hover-class="poll-editor-add-hover"`，**未追加** `press-spring`；
- WXSS 侧：`pages/post-publish/index.wxss:108` 的 `.poll-editor-add-hover { background: #f4f6f8; }` **只有背景色**，无 `scale(0.96)`、无 inset 阴影。

**影响**：该「添加」按钮只挂到了 `spring-btn`（释放回弹过渡），按压态没有物理压缩与凹陷质感，反馈退化为「仅背景变色」。这属于护栏设计的典型静默失效（不报错、只是没手感），不影响功能可用性，属**中低危交互缺陷**。

**连带发现（同一断言的第二处违规）**：本次还新增了未跟踪模块 `pages/market/`，其中 `pages/market/index.wxml:10` 使用 `hover-class="category-hover press-spring"`（已带 `press-spring`），但 `pages/market/index.wxss:7` 的 `.category-hover { background: #eef3fa; }` 同样缺 `scale(0.96)`。即：修好第 1 处后，`press-spring-shared.test.js` 的「每个 hover 类必须有 scale(0.96)」断言（`:140`）会紧接着在 `category-hover` 上失败。

**全站扫描量化（只读独立分析脚本，非测试文件）**：

| 指标 | 当前工作区 | 干净 HEAD |
|---|---|---|
| 交互元素挂 `spring-btn` | 278 | 277 |
| hover-class 追加 `press-spring` | 274 | 273 |
| hover 类总数 | **65** | 63 |
| hover 类缺 `scale(0.96)` | **2**（`poll-editor-add-hover`、`category-hover`） | 0 |
| 缺 `press-spring` 的 hover-class | **1**（`poll-editor-add-hover`） | 0 |
| 缺 `hover-stay-time` / 裸 `<button>` | 0 / 0 | 0 / 0 |

**修复建议（二选一）**：

1. 推荐：`hover-class="poll-editor-add-hover press-spring"`，同时给 `.poll-editor-add-hover`、`.category-hover` 补 `scale(0.96)` + inset 内阴影；或
2. 若刻意要自定义按压幅度，则按文档「方式二」保留并补齐样式，同时更新护栏文案。

### 5.2 `settings-publish-privacy.test.js`：测试断言陈旧（契约漂移，非产品缺陷）

**触发源**：`pages/profile/index.js` + `pages/profile/index.wxml`（本次未提交改动）

本轮改动把「隐藏主页帖子」从**设备本地开关（只作用于本人主页）**改为**服务端驱动的访客视角开关**：

| 维度 | HEAD（测试 D 断言的对象） | 当前工作区 |
|---|---|---|
| 读取来源 | `(wx.getStorageSync('system_settings') || {}).hideProfilePosts` | `profile.hideProfilePosts`（服务端 `/user/info`、`getProfile` 下发） |
| 语义 | 仅 `profileId === currentUserId` 时隐藏**本人**帖子 tab | `!isSelf && profile.hideProfilePosts` → 对**访客**隐藏 |
| 默认 tab | `activeTab: hideProfilePosts ? 1 : 0`（落到收藏） | 不再改默认 tab（tab 集合固定为「帖子/收藏」） |
| onShow 同步 | `hideProfilePosts !== this.data.hideProfilePosts` 时同步 | 改为 `loadPageData(true)` 重新拉取服务端标记 |
| WXML | `wx:if="{{!hideProfilePosts}}"`、`activeTab === 0 && !hideProfilePosts`、占位「已开启「隐藏主页帖子」」 | `visitorHidden`：统计项 `wx:if="{{!visitorHidden}}"`、tab 文案「已隐藏主页帖子」、空态「该用户已隐藏主页帖子」 |

**为什么判定为「测试陈旧」而非产品缺陷**：

- 服务端侧实现**在 HEAD 已完整存在**（非本次新增），且链路自洽：
  - `server/utils/migrations.js:67` 已建列 `sys_user.hide_profile_posts`；
  - `server/controllers/userController.js` `getProfile` 有 `hidePostsFromVisitor`（访客视角 `postCount` 归 0）；
  - `getProfilePosts` 对访客直接返回空列表（`:251-254`）；
  - `updateInfo` 接受并校验 `hideProfilePosts`，写入 `hide_profile_posts`；
  - `pages/settings/index.js`（**未改动**）本就从 `/user/info` 水合、并 `PUT /user/info` 落库。
- 本轮改动实质是**删掉冗余的客户端本地自隐藏逻辑**，让个人主页对齐服务端已实现的访客过滤语义。
- 但 `settings-publish-privacy.test.js` 的用例 D 仍逐字符串断言旧实现，且**本轮更新了另外 5 个测试文件**（`audit-state-fixes`、`driving-school-module`、`errand-order-privacy`、`home-entry-availability`、`liquid-tab-shared`），**遗漏了这一个**。

**影响**：产品功能未失效（访客确实拿不到帖子列表与帖子数）；但护栏失守 —— 旧契约与新行为的差异不再有人看守，后续任一侧再改都会「静默通过」。

**修复建议**：更新用例 D 的断言为目标行为（`visitorHidden`、`profile.hideProfilePosts`、新的 WXML 条件与文案）；若产品仍要求保留「本人主页隐藏帖子 tab」的旧交互，则应回退 `pages/profile/*` 源码而非改测试。

## 六、可能相关的问题点

### 6.1 测试门禁缺口（本次最值得优先处理）

`server/package.json` 的 `test` 脚本**手工串联 41 个文件**，而 `server/tests/` 实际有 **95 个**：

| 项目 | 数值 |
|---|---|
| `npm test` 串联的测试文件 | 41 / 95 |
| **未接入 `npm test` 的文件** | **54（56.8%）** |
| 本次两个失败套件是否在链中 | **均不在**（`press-spring-shared.test.js`、`settings-publish-privacy.test.js`） |

后果：`npm test` 全绿（exit 0）与「全量 93/95」并存，**门禁对新增护栏测试完全失明**。建议把 `test` 脚本改为自动收集执行，例如：

```json
"test": "node scripts/run-all-tests.js"
```

由脚本遍历 `tests/*.test.js` 逐个 spawn 并汇总退出码（正是本次报告使用的执行方式），避免每新增一个测试文件都要手工追加链式命令。

### 6.2 死代码：`closeComponentEditor` 已无绑定

同一处 `pages/post-publish/index.wxml` 改动把投票编辑器头部的关闭按钮 `<text class="sheet-close" bindtap="closeComponentEditor">×</text>` 替换为「添加」胶囊，导致 `pages/post-publish/index.js:209` 的 `closeComponentEditor()` **成为全仓唯一引用（无任何 WXML 绑定）**。

- **不是阻断性缺陷**：编辑器仍有 `tag-mask`（`bindtap="closeAllSheets"`）作为点击遮罩关闭路径，`closeAllSheets()` 会重置 `componentEditor: ''`。
- 但该 handler 已成为死代码，且投票编辑器变为**只能点遮罩关闭、无显式关闭按钮**，交互可发现性下降，建议确认是否有意为之。

### 6.3 未提交改动面较大，新模块缺少直接测试引用

工作区 59 项未提交改动中包含 8 项未跟踪新增条目，其中 3 个路径完全没有直接测试引用：

## 七、结论与建议

**结论**：全量 95 个测试文件中 93 通过、2 失败；失败均为**当前未提交工作区改动**引入，且在干净 HEAD 下均通过。官方 `npm test`（41 文件）与 `jw-crawler` 质量门、全仓语法门（306 文件 0 错误）全部通过 —— 但官方门禁因未收录这 54 个文件而**无法发现这两处回归**。

**建议优先级**：

1. **P0**：修复 `press-spring-shared.test.js` 触发的两处按压样式违规（`poll-editor-add-hover`、`category-hover`）——真实交互反馈缺陷，两行样式即可闭环。
2. **P0**：把 `npm test` 从手工 41 条链改为自动遍历 95 个文件，堵住门禁盲区。
3. **P1**：同步 `settings-publish-privacy.test.js` 用例 D 到服务端驱动的新语义（或回退 `pages/profile/*`），消除契约漂移。
4. **P1**：确认 `closeComponentEditor` 死代码与投票编辑器「无显式关闭按钮」是否为有意设计。
5. **P2**：为新增模块（`pages/market/`、`pages/driving-school/landing.*`、`wxacodeController.js`）与 6.4 清单中的高风险服务补测。

**修复后回归方法**：两个失败套件均为确定性失败，修复后重跑 `node server/tests/press-spring-shared.test.js` 与 `node server/tests/settings-publish-privacy.test.js` 即可确认；全量回归请按附录 A 逐文件执行方式复跑。
